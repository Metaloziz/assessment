# 1. Тема

**Стек и Hash-map:** LIFO · push/pop · ключ→значение · коллизии

---

# 2. Главное в одну фразу

Стек хранит порядок «последним пришёл — первым ушёл», hash-map даёт почти мгновенный доступ по ключу — вместе это база для скобок, DFS, подсчётов и поиска за O(1) в среднем.

---

# 3. Суть

> **Стек** — структура с доступом только к вершине: `push` кладёт сверху, `pop` снимает сверху (LIFO). Удобен, когда нужно помнить «незавершённый контекст»: вложенные скобки, откат пути в DFS, вычисление выражений, стек вызовов в рантайме.
>
> **Hash-map** (словарь, `Map` / объект) хранит пары ключ → значение. Хеш-функция переводит ключ в индекс корзины; в среднем `get` / `set` ≈ O(1). Цена — память, коллизии и то, что порядок обхода не обязан совпадать с порядком вставки (у обычного объекта — свои нюансы; у `Map` порядок вставки сохраняется).
>
> Типичная связка в задачах: один проход + `Map`/`Set` вместо двойного цикла; стек — когда важна вложенность или обратный порядок. Ловушка: считать хеш всегда O(1) на всём и забывать про коллизии / плохой ключ; у стека — читать «дно» вместо вершины или путать со очередью (FIFO).

---

# 4. Самое главное запомнить

- Стек = **LIFO**; очередь = FIFO — не путать.
- Операции стека: `push` / `pop` / `peek` — обычно O(1).
- Hash-map: ключ → значение; в среднем O(1) lookup, в худшем при деградации — O(n).
- `Set` — hash-map без полезной нагрузки (только «есть ключ?»).
- Скобки / path undo / mono-stack — частые сценарии стека.
- Частота, two-sum через `Map`, дедуп — частые сценарии хеша.
- В JS: массив как стек (`push`/`pop`); для словаря предпочитайте `Map`, если ключи не только строки.

# 5. Описание

## Стек

### Как устроен

Представьте стопку тарелок: кладёте только сверху, снимаете только сверху. Нижние недоступны, пока не снимете верхние.

```text
push 1 → [1]
push 2 → [1, 2]   ← верх = 2
pop    → [1]      вернули 2
```

В JS часто хватает массива:

```typescript
const stack: number[] = [];
stack.push(1);
stack.push(2);
const top = stack.pop(); // 2
const peek = stack[stack.length - 1];
```

### Зачем в алгоритмах

**Проверка скобок:** открывающую кладём в стек; на закрывающую снимаем и сверяем тип. Пустой стек в конце — ок.

```typescript
function isValid(s: string): boolean {
  const stack: string[] = [];
  const pair: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') stack.push(ch);
    else {
      if (stack.pop() !== pair[ch]) return false;
    }
  }
  return stack.length === 0;
}
```

**DFS вручную:** вместо рекурсии кладём вершины в стек (явный стек = тот же LIFO, что у вызовов).

**Монотонный стек:** в стеке индексы в возрастающем/убывающем порядке значений — «следующий больший элемент» и похожие задачи.

## Hash-map

### Как устроен

Ключ прогоняется через хеш → номер корзины. В корзине лежит значение (или цепочка при коллизии). Хороший хеш размазывает ключи; при росте таблицы делают rehash.

```text
"alice" ──hash──► bucket 3 → { age: 25 }
"bob"   ──hash──► bucket 7 → { age: 30 }
```

В TypeScript:

```typescript
const ages = new Map<string, number>();
ages.set('alice', 25);
ages.get('alice'); // 25
ages.has('bob'); // false
```

`Set` — те же корзины, но без значения: только факт присутствия.

### Зачем в алгоритмах

**Снять один множитель n:** вместо «для каждого i ищем пару в хвосте» — один проход и `Map` уже виденных чисел.

```typescript
function twoSum(nums: number[], target: number): [number, number] | null {
  const seen = new Map<number, number>(); // value → index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i]!;
    if (seen.has(need)) return [seen.get(need)!, i];
    seen.set(nums[i]!, i);
  }
  return null;
}
```

**Подсчёт частот:** `Map<T, number>` или объект-счётчик.

**Индекс / группировка:** ключ = id сущности, значение = запись или список.

### Коллизии и подводные камни

- Плохой хеш или много одинаковых корзин → операции ближе к O(n).
- Ключом объекта может быть только string/symbol; для произвольных ключей — `Map`.
- Мутабельный объект как ключ `Map` сравнивается по ссылке, не по полям.
- Не храните в хеше то, что дешевле посчитать за O(1) без памяти — иногда массив индексов проще.

## Стек vs Hash-map — когда что

| Нужно | Структура |
|-------|-----------|
| Вложенность, откат последнего действия | Стек |
| «Помнить, что уже видели» / частоты / id→данные | Hash-map / Set |
| Очередь обработки «кто раньше пришёл» | Queue (не стек) |

Часто используют **вместе**: DFS со стеком + `Set` посещённых вершин.
