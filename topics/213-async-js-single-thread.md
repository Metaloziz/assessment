# 1. Тема

**JS — однопоточный и синхронный язык**

---

# 2. Главное в одну фразу

JavaScript в браузере и Node исполняет ваш код в одном потоке синхронно по call stack, поэтому долгий синхронный цикл блокирует UI и обработку событий, а асинхронность нужна, чтобы отложить работу и не держать стек занятым.

---

# 3. Суть

> В типичном рантайме (браузерный JS, основной поток Node) **ваш** код идёт по одному **call stack**: пока функция не вернулась, следующая не стартует. Это и есть «однопоточный и синхронный» смысл модели: нет параллельного выполнения двух кусков вашего скрипта на одном стеке.
>
> Если занять стек долгим циклом или тяжёлым расчётом, страница не рисуется, клики и таймеры ждут — event loop не может забрать следующую задачу, пока стек не пуст. Сеть и таймеры при этом живут снаружи стека (Web APIs / libuv), но колбэк всё равно попадёт в очередь и выполнится только когда стек свободен.
>
> Асинхронные API (`setTimeout`, `fetch`, промисы) не делают JS многопоточным: они **откладывают** продолжение, чтобы стек успел опустеть и обработать другие события. Настоящий параллелизм — отдельно: `Worker`, процессы Node, нативный код движка.

---

# 4. Самое главное запомнить

- Один call stack: синхронный код идёт сверху вниз, вложенные вызовы кладутся в стек.
- Пока стек не пуст, event loop не запускает следующую задачу из очереди.
- Долгий `for` / тяжёлый sync-расчёт = «зависший» UI, даже если «где-то» идёт сеть.
- `setTimeout(fn, 0)` не прерывает текущий синхронный код — `fn` только после опустошения стека.
- Web Workers / `worker_threads` — другой поток со своим стеком, не «магия» обычного `async`.
- Асинхронность снимает блокировку стека; она не ускоряет сам CPU-bound алгоритм на одном потоке.

---

# 5. Описание

```text
синхронный код
  → вызовы кладутся в call stack
  → пока stack ≠ ∅, UI/таймеры/сеть-колбэки ждут
  → stack пуст → event loop берёт следующую задачу
```

## Call stack

Каждый вызов функции — кадр на стеке. Возврат снимает кадр. Рекурсия без базы раздувает стек до `RangeError`. Синхронность значит: тело функции выполняется целиком до `return`, без «паузы посередине» обычным JS (кроме `await` — это уже разбиение на микротаски, отдельная тема).

```js
function a() {
  b();
}
function b() {
  console.log('stack: a → b');
}
a();
```

## Блокировка UI

```js
const t0 = performance.now();
while (performance.now() - t0 < 3000) {
  /* 3 секунды синхронной работы */
}
console.log('кнопки не отвечали эти 3 с');
```

В DevTools Performance видно длинный «Long Task» на main thread. Лечение: резать работу на куски (`scheduler` / `setTimeout` между чанками), вынести в Worker, или не делать тяжёлое на клике без необходимости.

## Где «многопоточность» всё же есть

Движок и хост делают I/O, таймеры, декодирование в других потоках. Ваш колбэк всё равно сериализуется на main thread. Не путать: «запрос ушёл параллельно» ≠ «JS считает два массива одновременно».

## Ловушка

Фраза «JS однопоточный» относится к **модели исполнения скрипта**, а не к тому, что в процессе ОС один поток. Worker — исключение с отдельным стеком и без прямого доступа к DOM.
