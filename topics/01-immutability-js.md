# 1. Тема

**Преимущества и минусы иммутабельности данных в JavaScript**

---

# 2. Главное в одну фразу

Иммутабельность делает состояние предсказуемым и удобным для сравнения по ссылке, но каждое обновление стоит новых аллокаций и более аккуратного кода для вложенных структур.

---

# 3. Суть

> Иммутабельность в JavaScript — это соглашение: объекты и массивы после создания не правят «на месте», а при изменении собирают новую версию данных (часто с частичным переиспользованием старых ссылок).
>
> Так проще рассуждать о state в React и Redux: функция не ломает чужой объект, DevTools может хранить историю снимков, а `memo` / `PureComponent` сравнивают `prev === next` без глубокого обхода.
>
> Цена — больше аллокаций и громоздкие nested-обновления без Immer; для локальных буферов в цикле мутация часто уместнее. Ошибка новичка — `{ ...obj }` считает «глубокой» копией, хотя вложенные объекты остаются общими.

---

# 4. Самое главное запомнить

- **Иммутабельность** = не мутируем старое значение, создаём новое.
- **Плюс для UI** — предсказуемость, безопасная передача, сравнение по ссылке (`===`).
- **Плюс для отладки** — снимки state, time-travel, проще тесты чистых функций.
- **Минус** — аллокации; nested updates без Immer громоздки; на больших данных глубокие копии дороги.
- **Shallow copy** (`{...obj}`, `[...arr]`) не клонирует вложенность.
- Практика: иммутабельно — global/UI state; мутабельно — локальные временные структуры.
- Инструменты: spread / `structuredClone` (редко для state) / **Immer**; Immutable.js — редко.

---

# 5. Описание

## Мутация vs новая версия

```javascript
const user = { name: 'Anna', age: 25 };
user.age = 26; // мутация: все держатели той же ссылки видят 26

const next = { ...user, age: 26 }; // новый объект; user.age всё ещё 25
```

В React `setState(user)` после `user.age = 26` часто **не** перерисует: ссылка та же, React не видит смены state.

## Почему это важно в UI

```text
state v1 ──► компонент / selector
                │
update (immutable) ──► state v2 (новая ссылка)
                │
              memo: v1 !== v2 → пересчёт / рендер
```

1. **Предсказуемость** — данные не «подменяются» за спиной вызывающего.
2. **Сравнение по ссылке** — дешёвый сигнал «что-то изменилось».
3. **История** — undo/redo и Redux DevTools опираются на смену ссылок, а не на мутацию одного объекта.
4. **Тесты** — чистая функция `(state, action) => nextState` без скрытых side effects.

## Цена и ловушки

| Проблема | Суть |
|----------|------|
| Память | Каждое обновление аллоцирует хотя бы новый «корень» / затронутые уровни |
| Nested update | Без Immer — цепочки spread на каждом уровне |
| Shallow copy | `{ ...post, author: post.author }` — `author` всё ещё общий объект |
| Hot path | В тесном цикле мутация локального аккумулятора обычно быстрее |

Пример ловушки shallow copy:

```javascript
const a = { profile: { city: 'Berlin' } };
const b = { ...a };
b.profile.city = 'Prague'; // и a.profile.city тоже 'Prague'
```

## Как обновлять вложенность

**Вручную (громоздко):**

```javascript
const next = {
  ...state,
  user: {
    ...state.user,
    address: { ...state.user.address, zip: '10115' },
  },
};
```

**Immer (стандарт в RTK):**

```javascript
import { produce } from 'immer';

const next = produce(state, (draft) => {
  draft.user.address.zip = '10115';
});
```

Пишете «как мутацию», на выходе — новый иммутабельный state; нетронутые ветки сохраняют старые ссылки (structural sharing на уровне Immer).

## Баланс на практике

- **Иммутабельно:** Redux/Zustand store, React state/props, кэш UI, всё что шарят несколько подписчиков.
- **Мутабельно:** локальные переменные функции, черновик в `produce`, TypedArray/буферы с явным контролем, одноразовые структуры в алгоритме.

Иммутабельность — не догма языка (JS по умолчанию мутабелен), а дисциплина слоя состояния.

## Типичные вопросы на собеседовании

- Зачем иммутабельность в React? — Чтобы смена ссылки гарантировала сигнал обновления и безопасные сравнения в `memo`.
- Чем плох только spread? — Неглубокая копия; вложенные объекты остаются общими.
- Immer «мутирует»? — В `draft` пишете мутабельно; снаружи получаете новый immutable state.
- Всегда ли копировать? — Нет: локальные вычисления и hot path часто мутируют без вреда.
