# 1. Тема

**Преимущества и минусы иммутабельности данных в JavaScript**

---

# 2. Главное в одну фразу

Иммутабельность делает состояние предсказуемым и безопасным для отладки, но за это вы платите дополнительными аллокациями памяти и более сложным кодом обновления вложенных структур.

---

# 3. Суть

> «Иммутабельность в JavaScript означает, что мы не изменяем существующие объекты и массивы напрямую, а создаём новые версии данных при каждом обновлении.
>
> **Плюсы:**
> - **Предсказуемость** — проще понять, откуда пришло текущее состояние;
> - **Безопасность при передаче** — функция не ломает исходный объект;
> - **Отладка и time-travel** — история изменений в Redux/DevTools;
> - **Оптимизация рендеринга** — сравнение по ссылке в React;
> - **Проще тестировать** — чистые функции со стабильным результатом.
>
> **Минусы:**
> - **Дополнительная память** — каждое обновление создаёт новый объект/массив;
> - **Сложнее обновлять вложенные структуры** — без Immer код громоздкий;
> - **Производительность на больших данных** — частые глубокие копии дороги;
> - **Не всегда нужно** — для локальных временных переменных мутация проще.
>
> На практике в React и state management выбирают иммутабельный подход для UI-состояния, а мутацию оставляют для локальных короткоживущих операций.»

---

# 4. Самое главное запомнить

- **Иммутабельность** = не меняем старые данные, а создаём новые.
- **Главный плюс** — предсказуемость, отладка, сравнение по ссылке (`===`).
- **Главный минус** — лишние копии и сложность вложенных обновлений.
- В **React** важна для корректных обновлений state и `memo`.
- Для вложенных структур: **spread**, **Immer**, реже Immutable.js.

---

# 5. Описание

## Мутация vs иммутабельность

```javascript
const user = { name: 'Anna', age: 25 };
user.age = 26; // мутация

const updatedUser = { ...user, age: 26 }; // новый объект
```

## Плюсы

1. Предсказуемость и отсутствие побочных эффектов.
2. Сравнение по ссылке (`prev === next`) для React/`memo`.
3. История изменений (Redux, undo/redo).
4. Проще reasoning в больших приложениях.

## Минусы

1. Расход памяти на новые структуры.
2. Громоздкие nested updates без Immer.
3. Shallow copy (`{...obj}`) не защищает вложенные объекты.
4. Не оправдано для локальных вычислений в циклах.

## Баланс на практике

- **Иммутабельно:** global state, props, Redux reducers.
- **Мутабельно:** локальные переменные, временные буферы, hot path с контролем.
