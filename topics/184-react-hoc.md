# 1. Тема

**Компоненты высшего порядка**

---

# 2. Главное в одну фразу

Компонент высшего порядка — функция, которая надевает на готовый экран общую логику и отдаёт новый тип, не правя исходник.

---

# 3. Суть

> Компонент высшего порядка (**HOC**, higher-order component) — это не экран и не «родитель с детьми», а фабрика. Функция берёт готовый компонент и возвращает новый: тот рисует старый и добавляет поведение снаружи — проверку входа, данные, лог — не открывая файл обёрнутого экрана.
>
> Одна оболочка надевается на разные страницы. Профиль и настройки должны знать, вошёл ли человек: вместо копирования проверки пишут `withAuth` и оборачивают нужные экраны. Так раньше работали `connect` в React-Redux и `withRouter` в старом React Router.
>
> `withAuth(Profile)` создаёт `WithAuth`. Нет сессии — рисуют Login, `Profile` не монтируется; есть — `<Profile {...props} user={user} />`. Имя обёртки в DevTools задают через `displayName`.
>
> Если вызвать фабрику в теле `render` родителя, каждый раз получается новый тип — React снимает дерево, state внутри сбрасывается. `ref` и статичные поля через обёртку сами не протекают. Для своей логики в новом коде чаще пишут хук `useAuth`; HOC остаётся, когда нужно надеть поведение на чужой компонент без доступа к его исходнику.

---

# 4. Самое главное запомнить

- HOC — функция `(Component) => Component`, не родитель, который рисует `{children}`.
- Обёрнутый компонент не мутируют: возвращают новую обёртку.
- Неизвестные props пробрасывают `{...props}`, иначе `className` и `onClick` не дойдут.
- Фабрику не вызывают в теле `render`: новый тип каждый раз → сброс state.
- `ref` и static-поля сами не протекают — нужны `forwardRef` и копирование static.
- Для новой логики в своём коде чаще пишут custom hook; HOC — когда нет доступа к исходнику.

---

# 5. Описание

```text
withAuth(Profile)  →  WithAuth(props)
                         │
                         ├─ нет user  →  <Login />
                         └─ есть user →  <Profile {...props} user={user} />
```

Обёртка — отдельный компонент. Исходный `Profile` не знает про сессию: его вызывают уже с готовым `user` или не вызывают вовсе.

## Что возвращает фабрика

```tsx
const withAuth = (Wrapped: ComponentType<ProfileProps>) => {
  const WithAuth = ({ user, ...rest }: AuthProps) => {
    if (!user) return <Login />;
    return <Wrapped {...rest} user={user} />;
  };
  WithAuth.displayName = `withAuth(${Wrapped.displayName ?? Wrapped.name})`;
  return WithAuth;
};

const AuthedProfile = withAuth(Profile);
```

`withAuth` вызывают **один раз** при загрузке модуля. `AuthedProfile` — стабильный тип: React сравнивает его между рендерами и не путает с соседними экранами.

## Зачем надевать снаружи

Одна и та же проверка или подписка нужна нескольким экранам, а править каждый файл нельзя или не хочется: библиотечный виджет, старый класс, общий «пояс» аналитики. Обёртка держит ветку «пускать / не пускать» и внедряет результат через props. Экраны остаются про данные и вёрстку.

Рядом другие способы делить поведение — их не смешивают с HOC:

| Подход | Что меняется | Когда уместен |
| --- | --- | --- |
| HOC | появляется новый тип компонента | надеть логику на чужой/готовый экран |
| Custom hook | только логика, дерево то же | свой код на функциях |
| Родитель + `{children}` | разметка вокруг слота | каркас страницы, не фабрика |

Render-props и compound components — отдельные темы: там UI остаётся в JSX вызывающего, а не за новым типом `EnhancedPage`.

## Чтобы не сломать дерево

Фабрику нельзя создавать в теле родителя. Каждый вызов `withX(Child)` — **новая функция-компонент**. Для React это другой тип: старое дерево снимают, монтируют заново. Счётчик, черновик, фокус — обнуляются.

```tsx
const Parent = () => {
  const Enhanced = withX(Child); // плохо: новый тип на каждый render
  return <Enhanced />;
};
```

Неизвестные props всегда пробрасывают: обёртка забирает только своё (`user`, `isLoading`) и отдаёт остальное вниз. Иначе обёрнутый «глухой» к `className` и обработчикам.

`ref` указывает на обёртку, не на DOM внутри `Wrapped`, пока не сделать `forwardRef`. Статичные поля (`Child.fetch`) тоже не копируются сами — их переносят явно или через `hoist-non-react-statics`. Порядок нескольких обёрток важен: `withA(withB(Page))` — сначала внутренняя `withB`.
