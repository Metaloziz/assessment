# 1. Тема

**Замыкание, возможные проблемы**

---

# 2. Главное в одну фразу

Замыкание сохраняет доступ к внешним переменным, но требует контролировать изменяемое состояние, переменные циклов и время жизни ссылок.

---

# 3. Суть

> «Замыкание возникает, когда функция продолжает обращаться к переменным внешней области видимости после завершения внешней функции. Так удобно делать приватное состояние, фабрики и коллбэки.
>
> Типичные ошибки — ожидать снимок значения вместо живой переменной, использовать `var` в асинхронном цикле или долго удерживать через обработчик крупный объект. Использую `let` для отдельной переменной итерации, уменьшаю область замыкания и снимаю ненужные подписки.»

---

# 4. Самое главное запомнить

- Замыкание хранит связь с переменной, а не её копию.
- Каждый вызов внешней функции создаёт своё отдельное состояние.
- `var` в цикле создаёт одну переменную на всю функцию; `let` — новую на итерацию.
- Слушатель на долгоживущем объекте может удерживать данные в памяти.
- Само замыкание не является утечкой; утечка возникает из ненужной достижимой ссылки.

---

# 5. Описание

```js
function createCounter() {
  let count = 0;
  return () => ++count;
}

const first = createCounter();
first(); // 1
first(); // 2
```

Проблема `var` в асинхронном цикле:

```js
for (var i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3
}

for (let i = 0; i < 3; i += 1) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2
}
```

| Риск | Как избежать |
|---|---|
| общее изменяемое состояние | делайте API явным, используйте `const` где возможно |
| неверный индекс в цикле | используйте `let` |
| удержание данных слушателем | удаляйте слушатели и обнуляйте долгие ссылки |
