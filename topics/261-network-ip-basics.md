# 1. Тема

**Базовое понимание IP**

---

# 2. Главное в одну фразу

IP — это «почтовый адрес» компьютера в сети: пакеты идут по числам и по размеру сети (`/24`), а не по имени сайта и не по порту программы.

---

# 3. Суть

> **IP** — способ сказать, *кому* в сети адресован пакет. Адрес выглядит как число: `10.0.2.15` (IPv4) или длинная запись IPv6. Сам по себе адрес мало что значит: его читают вместе с **префиксом** — записью вроде `10.0.2.15/24`. Число после `/` показывает, где «моя улица», а где уже «чужой район».
>
> Это видно в работе, когда контейнер не достаёт БД в другой подсети, firewall режет целый диапазон адресов, а в логе сервера один IP, хотя пользователь клянётся, что сидит с другого. Docker, облако и ACL смотрят на адрес и маску, не на hostname и не на путь в URL.
>
> Как это работает. Хост кладёт в пакет «откуда» и «куда». Если «куда» в той же сети по префиксу — пакет идёт соседу напрямую. Если нет — на **шлюз** (роутер), а дальше по цепочке. Частные адреса вроде `10.x` и `192.168.x` в интернет сами не выходят: на границе их обычно подменяет **NAT** на один публичный адрес.
>
> Ловушка: путать IP с именем сайта (это DNS) и с портом процесса (это транспорт). `10.x` в логе бэка часто адрес после NAT или сосед по мосту, а не «IP ноутбука пользователя». `/16` и `/24` — разный размер сети, не две записи одного адреса.

---

# 4. Самое главное запомнить

- IP указывает на *узел* (машину/интерфейс), не на программу и не на путь `/api`.
- Адрес читают с префиксом: `10.0.2.15/24` значит «я в сети `10.0.2.0/24`», не «просто четыре числа».
- Совпал префикс → сосед в той же сети; не совпал → пакет уходит на шлюз.
- Чем больше число после `/`, тем уже сеть: `/24` точнее `/16`; запасной выход — «всё остальное» (`0.0.0.0/0`).
- Адреса `10…`, `172.16…`, `192.168…` — частные: снаружи их не маршрутизируют без NAT или VPN.
- После NAT в логе бэка часто виден IP офисного/домашнего шлюза, а не ноутбук пользователя.
- `127.0.0.1` — только эта машина; `169.254…` — «локально без нормального DHCP», не интернет.

# 5. Описание

```text
пакет: от 10.0.2.15  →  куда ?
                 │
        «куда» в моей сети
            (/24)?
           /          \
     да: сосед      нет: шлюз
     (та же сеть)   (дальше роутер / NAT)
```

## Зачем IP и префикс

Люди пишут имена (`api.example.com`), а сеть доставляет пакеты по числу — IP. Имя уже должно стать адресом (тема DNS / hostname). Здесь важен следующий шаг: **куда слать**, когда адрес уже есть.

Число после `/` — длина **префикса** (часто говорят **CIDR**). Это не «вторая половина адреса», а ответ: сколько старших бит общие у «соседей». `/24` — типичная домашняя или Docker-сеть; `/16` — гораздо шире; `/32` — один конкретный хост.

```text
10.0.2.15/24
│         └── «квартиры» (хосты)
└── «улица» (сеть)  →  10.0.2.0

сеть:      10.0.2.0
broadcast: 10.0.2.255
хосты:     10.0.2.1 … 10.0.2.254
```

**Маска** — та же идея другими словами: `/24` = `255.255.255.0`. Проверка «в одной ли сети?» — не «цифры похожи», а совпадение по префиксу. Поэтому `10.0.2.40` рядом с `10.0.2.15/24`, а `10.0.3.40` — уже другая сеть: пакет пойдёт через шлюз.

| Префикс | О чём это | Типично |
| --- | --- | --- |
| `/32` | один хост | правило в ACL / маршрут на машину |
| `/24` | небольшая сеть (~256 адресов) | LAN, Docker-мост |
| `/16` | большая сеть | крупная подсеть, VPC |
| `/0` | «всё остальное» | default route в интернет |

Запись `10.0.2.15/24` на интерфейсе значит: «мой адрес `10.0.2.15`, соседи — вся `10.0.2.0/24`». Куда слать, решают по **адресу назначения** в пакете, не по имени сервера.

## Частные адреса и NAT

Часть адресов зарезервирована под «внутренние» сети (`10…`, `172.16…`–`172.31…`, `192.168…`). Их не объявляют как маршруты в публичный интернет: пакет с `src 10.0.2.15` снаружи «неоткуда» и «некуда».

**NAT** на границе подставляет вместо частного адреса публичный IP шлюза (часто ещё и порт). Много ноутбуков дома выходят «как один» внешний адрес. Обратный проброс (чтобы с интернета достучаться до внутреннего сервиса) настраивают отдельно; без него входящий пакет на `10.x` из интернета не дойдёт.

Отсюда привычная картина: у вас открывается `localhost` или `10.x`, а у клиента снаружи — нет. И ещё: IP в access-логе бэка после NAT часто адрес шлюза (офис, оператор), не машина пользователя. NAT не заменяет шифрование и не делает трафик «анонимным» — он только меняет адреса.

## IPv4 и IPv6 в двух словах

| | IPv4 | IPv6 |
|---|---|---|
| Как выглядит | `203.0.113.10` | длиннее, нули сжимают: `2001:db8::10` |
| Частные | `10…`, `192.168…` и др. | свои «локальные» диапазоны |
| Loopback | `127.0.0.1` | `::1` |

На практике часто работают оба сразу. Клиент может пойти по IPv6, а правило firewall написано только под IPv4 — «у одних открывается, у других нет».

## Особые адреса

| Адрес / диапазон | Смысл простыми словами |
| --- | --- |
| `127.0.0.1`, `::1` | эта же машина |
| `10…`, `172.16…`, `192.168…` | частная сеть (дом, офис, Docker, VPC) |
| `169.254…` | «временный локальный», часто когда DHCP не выдал адрес |
| обычный публичный | может маршрутизироваться в интернет (если ACL/NAT не мешают) |

Сервис, слушающий только `127.0.0.1`, с другой машины и из другого контейнера не увидят — это не баг сети, а «только я».

## Куда хост шлёт пакет

Упрощённо:

1. Назначение в моей сети по префиксу → сосед напрямую.
2. Иначе → шлюз (или маршрут «по умолчанию» в интернет).
3. По пути счётчик «сколько хопов осталось» уменьшается; обрыв пути — сетевая ошибка, не HTTP `404`.

Имя к этому шагу уже должно стать IP. Модель уровней TCP/IP — соседние темы; здесь важен **сам адрес**: префикс, частный/публичный, NAT.

## Ловушки

- Сравнивать адреса «на глаз» (`10.0.2.5` «похоже» на `10.0.2.50`) вместо проверки префикса.
- Ждать, что частный IP из лога бэка — IP пользователя в интернете.
- Открыть порт на `127.0.0.1` и удивляться, что соседний контейнер не коннектится.
- Написать ACL только на IPv4, когда клиенты ходят и по IPv6.
- Путать «нет маршрута» (IP) с «порт закрыт» (транспорт) и с `404` (HTTP).

Имя vs адрес — тема «IP-адрес и hostName». Как имя становится адресом — «Базовое понимание DNS». Здесь — **как читают адрес и куда уходит пакет**.
