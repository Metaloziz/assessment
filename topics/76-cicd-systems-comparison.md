# 1. Тема

**Системы CI/CD вне банковского стека: плюсы и минусы**

---

# 2. Главное в одну фразу

CI/CD-систему выбирают не по популярности, а по требованиям к размещению, безопасности, экосистеме репозитория, сложности pipeline и стоимости эксплуатации.

---

# 3. Суть

> Jenkins даёт максимальную свободу self-hosted-настройки и интеграций, но требует собственной эксплуатации. GitLab CI/CD и GitHub Actions удобны, когда код уже находится на соответствующей платформе: pipeline хранится в YAML рядом с репозиторием и тесно связан с merge request или pull request.
>
> Azure DevOps логичен для организаций с Microsoft/Azure-контуром; TeamCity ценят команды из экосистемы JetBrains; Travis CI остаётся простым облачным вариантом, но для новых проектов обычно реже выбирается, чем GitHub Actions или GitLab CI/CD.
>
> В банке приоритетны self-hosted или изолированное развёртывание, аудит, RBAC, секреты, контроль runners и интеграция с внутренними инструментами. Стартап обычно выигрывает от минимальной операционной нагрузки и нативной интеграции с хостингом репозитория.

---

# 4. Самое главное запомнить

- Jenkins гибок и бесплатен как продукт, но требует серверов, плагинов, обновлений и поддержки.
- GitLab CI/CD удобен внутри GitLab и поддерживает self-managed и SaaS-сценарии.
- GitHub Actions нативно связан с GitHub, pull request и Marketplace actions.
- Azure DevOps особенно удобен при Azure, Entra ID и Microsoft-инструментах.
- TeamCity имеет зрелый UI и сильную интеграцию с JetBrains, но коммерческая модель важна для оценки.
- Travis CI быстро начать, но его экосистема и частота выбора для новых проектов уступают лидирующим платформам.

---

# 5. Описание

## Сравнение систем

| Система | Тип | Бесплатность | Гибкость | Сложность настройки | Интеграции |
|---|---|---|---|---|---|
| Jenkins | Self-hosted, open source | Да, без лицензии; инфраструктура оплачивается отдельно | Высокая | Высокая | Плагины, Docker, Kubernetes, SonarQube, Vault и корпоративные системы |
| GitLab CI/CD | SaaS или self-managed | Community/self-managed и ограниченные SaaS-возможности | Средняя-высокая | Средняя | GitLab, Container Registry, security-функции, Kubernetes |
| GitHub Actions | Облачная и self-hosted runners | Для open source доступен широко; private usage лимитируется планом | Высокая | Средняя | GitHub, Marketplace, облачные провайдеры |
| Azure DevOps | Облачная/серверная платформа | Есть базовые бесплатные возможности, масштабирование платное | Высокая | Средняя | Azure, Entra ID, Boards, Artifacts, Microsoft-стек |
| TeamCity | Self-hosted/облачная коммерческая система | Ограниченная бесплатная редакция, коммерческие лицензии | Средняя | Низкая-средняя | JetBrains IDE, VCS, облака, контейнеры |
| Travis CI | Облачная система | Условия зависят от тарифа и типа проекта | Низкая-средняя | Низкая | GitHub, GitLab и популярные языковые экосистемы |

Цены, лимиты и состав конкретных security-функций меняются, поэтому перед закупкой или архитектурным решением их нужно сверять по актуальному тарифу и требованиям компании.

## Jenkins

Открытый CI/CD-сервер, где pipeline описывают в Jenkinsfile на Groovy/Declarative Pipeline. Сильная сторона — возможность встроить почти любой внутренний инструмент через плагин, API или скрипт. Минус — команда отвечает за controller, agents, обновления, плагины, резервное копирование и безопасность.

Подходит для сложного корпоративного и банковского контура, если есть компетенция эксплуатации и нужна автономность.

## GitLab CI/CD

Pipeline описывается в `.gitlab-ci.yml`, а runners выполняют jobs. Удобны единая модель merge request, registry, environments и security-отчётов. Self-managed GitLab помогает оставить код и runners во внутреннем контуре.

Ограничение — сильная привязка к GitLab и необходимость поддерживать GitLab/Runners при self-managed-модели. Для очень нестандартных процессов Jenkins иногда гибче.

## GitHub Actions

Workflow хранится в `.github/workflows/*.yml` и запускается на GitHub events: push, pull request, release, schedule. Широкий Marketplace быстро даёт готовые шаги для сборки, тестов и облаков.

Главный компромисс — зависимость от GitHub и SaaS-лимитов. Для чувствительных задач можно использовать self-hosted runners, но их безопасность становится ответственностью команды: недоверенный код из pull request не должен получать production-секреты.

## Azure DevOps

Azure Pipelines сочетается с Azure Repos, Boards, Artifacts и Azure-инфраструктурой. Удобен для .NET-ландшафта и организаций, уже использующих Entra ID, Azure и Microsoft-лицензирование.

Минус — продукт может оказаться избыточным для маленькой команды, а наибольшая выгода проявляется именно внутри экосистемы Microsoft.

## TeamCity

TeamCity — продукт JetBrains с развитым пользовательским интерфейсом, шаблонами конфигурации и сильной интеграцией с IDE JetBrains. Его часто выбирают команды Java/.NET, которым важна удобная диагностика сборок.

Нужно учитывать лицензионную модель, а для очень специфичных интеграций гибкость может быть ниже, чем у Jenkins.

## Travis CI

Travis CI использует `.travis.yml` и позволяет быстро настроить стандартные проверки, особенно для небольших проектов. Его проще освоить, но для сложных enterprise-процессов и новых репозиториев чаще рассматривают GitHub Actions, GitLab CI/CD или другие более активно развиваемые варианты.

## Как выбирать

| Контекст | Частый рациональный выбор | Почему |
|---|---|---|
| Банк, закрытый контур, много внутренних систем | Jenkins или GitLab self-managed; иногда Azure DevOps Server | Контроль размещения, аудит, RBAC, кастомные интеграции |
| Стартап на GitHub | GitHub Actions | Малые операционные затраты и нативные события PR |
| Команда на GitLab | GitLab CI/CD | Репозиторий, MR и pipeline в одном контуре |
| Microsoft/Azure-организация | Azure DevOps | Единая идентификация и облачная интеграция |
| Java/.NET-команда с JetBrains-стеком | TeamCity | Удобные UI и инструменты JetBrains |

Независимо от системы, обязательны: неизменяемые версии артефактов, отдельные учётные записи и права для сред, защищённые секреты, проверка зависимостей и образов, логи аудита, мониторинг после деплоя и tested rollback.

## Короткий ответ на собеседовании

«Jenkins выбирают за self-hosted-гибкость и плагины, но его нужно администрировать. GitLab CI/CD и GitHub Actions удобнее, когда репозиторий уже на соответствующей платформе: YAML находится рядом с кодом и связан с MR/PR. Azure DevOps особенно хорош в Microsoft-контуре, TeamCity — в JetBrains-стеке, Travis CI подходит для простых сценариев. В банке я прежде всего оцениваю изоляцию, аудит, RBAC, управление секретами и интеграцию с внутренними системами, а в стартапе — скорость запуска и стоимость эксплуатации».
