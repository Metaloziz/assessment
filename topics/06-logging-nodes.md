# 1. Тема

**Принцип выделения программных узлов, которые необходимо логировать**

---

# 2. Главное в одну фразу

Логировать нужно не весь код, а границы системы и критические точки: вход/выход данных, решения, ошибки и изменение состояния — там, где лог даёт максимум для отладки и мониторинга.

---

# 3. Ответ для собеседования

> «Программный узел — значимая точка: API endpoint, сервис, middleware, интеграция, бизнес-операция.
>
> Логируем: входы/выходы, решения (auth, validation), смену состояния, ошибки, внешние API.
> Не логируем: каждую строку цикла, простые утилиты, секреты.
>
> У каждого лога — контекст: `requestId`, `userId`, операция, результат, уровень (`debug`/`info`/`warn`/`error`). Цель — по одному `requestId` восстановить путь запроса.»

---

# 4. Самое главное запомнить

- Логируют **границы** и **критические точки**.
- Контекст: `requestId`, `userId`, `operation`.
- Уровни: debug → info → warn → error.
- Не логировать секреты/PII без маскировки.
- Цель — восстановить путь запроса.

---

# 5. Описание

## Какие узлы

1. Границы: HTTP, queue, cron, CLI.
2. Бизнес-события: заказ, оплата, регистрация.
3. Решения: auth, cache hit/miss, fallback.
4. Ошибки с контекстом.
5. Интеграции (stripe, email, CRM).

## Алгоритм выбора

1. Нарисовать поток запроса.
2. Отметить входы/выходы, бизнес-события, интеграции, ошибки.
3. Задать уровень и поля контекста.
4. Убрать шум.

Приоритет: ошибки → бизнес-события → границы → интеграции → debug.
