# 1. Тема

**Дизайн-система:** токены · примитивы · контракт UI

---

# 2. Главное в одну фразу

Дизайн-система — общий контракт продукта: токены задают значения, примитивы их используют, экраны не изобретают свой primary и radius.

---

# 3. Суть

> **Дизайн-система** на фронте — не «набор красивых макетов в Figma», а **контракт**: именованные значения (токены цвета, типа, пространства, радиуса) + переиспользуемые UI-примитивы (`Button`, `Field`, `Badge`) + правила, когда какой вариант брать. Без контракта каждая страница и каждая лаба копируют hex и локальные `.btn` — через месяц primary уже три разных.

> Зачем: один look на весь продукт, быстрее собирать экраны, проще менять бренд (поправили `--accent` — уехало везде). Дизайнер и разработчик говорят на одном словаре: `primary`, `space-3`, `radius-lg`, а не «та синяя чуть светлее».

> Как обычно устроено. Снизу **foundation** — CSS-переменные или тема (`tokens.css` / Theme). Поверх — **примитивы** с API (`variant`, `size`), которые читают только `var(--…)`. Дальше — составные блоки и уже экраны. Документ темы (THEME) фиксирует решения: одна кнопка, hex только в токенах, шкала из 5–6 ступеней, не из двенадцати.

> Ловушка: держать «дизайн-систему» только в Figma, а в коде — три параллельные кнопки и хардкод `#2f5f8f` рядом с `#69b1ff`. Или назвать токеном всё подряд (`--sidebar-item-label-0-62rem`) вместо короткой шкалы. Система — это **один** primary и запрет hex вне токенов, а не папка `components/` сама по себе.

---

# 4. Самое главное запомнить

- Токен = именованное значение (`--btn-primary-bg`), не «цвет в макете».
- Примитив (`LabButton`) читает токены; экран не пишет свой hex primary.
- Слои: foundation → primitives → patterns → screens; не прыгать через слой копипастой CSS.
- Одна кнопка / один радиус-lg для контролов — лучше трёх «почти одинаковых».
- Hardcoded hex вне `tokens.css` (и вне темы редактора кода) — признак дрейфа системы.
- Figma-kit без кода — гайд; живая система — токены + компоненты в репозитории.

---

# 5. Описание

```text
  Figma / макеты          ← визуальный источник (опционально)
        │
        ▼
  tokens.css / тема       ← foundation: цвет, тип, space, radius
        │
        ▼
  Button · Field · Badge  ← primitives: API + var(--…)
        │
        ▼
  Panel · Form · Viz      ← patterns (составные)
        │
        ▼
  экраны / лабы           ← только сборка, без новых hex
```

## Токены (foundation)

Токены — словарь продукта. Типичные группы:

| Группа | Примеры | Роль |
| --- | --- | --- |
| Цвет | `--bg-deep`, `--text`, `--accent`, `--ok` | фон, текст, семантика |
| Кнопка | `--btn-primary-bg`, `--btn-ghost-border` | все варианты одного контрола |
| Тип | `--font-sans`, `--font-size-body`, `--font-weight-semibold` | шкала, не россыпь `0.62rem` |
| Пространство | `--space-1` … `--space-6` | отступы |
| Радиус | `--radius-sm`, `--radius`, `--radius-lg` | инлайн-код / карточка / кнопка |

Правило: в компонентах и страницах — `var(--token)`, а не `#69b1ff`. Меняете бренд — правите один файл.

## Примитивы

Примитив — маленький контракт API поверх токенов:

```tsx
<LabButton variant="primary" size="sm">
  Запустить
</LabButton>
```

`variant` и `size` уже завязаны на `--btn-*` и `--radius-lg`. Новый экран **не** добавляет `.myPrimaryBtn { background: #2f5f8f }`.

Типичный набор: кнопка, поле ввода, бейдж, лог/алерт, панель схемы. Уникальные SVG-графы и метафоры лаб в «систему» не выносят — только chrome и состояния узла.

## Контракт vs UI-kit

| | UI-kit / библиотека | Дизайн-система |
| --- | --- | --- |
| Что даёт | компоненты | токены + компоненты + правила |
| Смена бренда | править много CSS | править foundation |
| Параллельные кнопки | часто появляются | запрещены контрактом |

Библиотека без токенов быстро превращается в свалку пропсов. Токены без примитивов остаются «переменными, которые никто не использует».

## Типичный дрейф

```text
Экран A:  LabButton + --btn-primary-*
Экран B:  .shell.btn  + другие hex
Экран C:  .uiBtn     + radius 4 вместо 8
        → три «primary», один продукт
```

Лечение: выбрать канон (одна кнопка), вынести цвета в токены, мигрировать потребителей, удалить старые классы. Документ темы должен совпадать с `tokens.css`, а не описывать устаревший look.

## Что не смешивать

- Тема синтаксиса редактора (CodeMirror / Prism) — отдельный набор, не chrome-токены.
- Семантика лога (`--log-ok`) ≠ цвет подсветки языка в сниппете.
- «Ещё одна ступень шрифта для сайдбара» — сначала проверить, хватает ли `--font-size-ui-xs` / `ui-sm` / `ui`.
