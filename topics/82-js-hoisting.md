# 1. Тема

**Всплытие переменных**

---

# 2. Главное в одну фразу

Hoisting означает, что объявления учитываются при создании контекста до выполнения кода, но их доступность зависит от вида объявления.

---

# 3. Суть

> «Термин “всплытие” — упрощённая модель: строки кода физически никуда не переносятся. Движок сначала создаёт привязки имён в области видимости, затем исполняет код.
>
> `var` сразу получает `undefined`, Function Declaration — готовую функцию, а `let` и `const` существуют, но до инициализации находятся в temporal dead zone. Поэтому обращение к ним раньше даёт `ReferenceError`.»

---

# 4. Самое главное запомнить

- У `var` всплывает объявление, а присваивание остаётся на месте.
- Function Declaration доступна целиком до объявления.
- `let` и `const` тоже создаются заранее, но TDZ запрещает чтение.
- Function Expression подчиняется правилам переменной, которой присвоена.
- Лучшее решение проблем hoisting — объявлять значение до первого использования.

---

# 5. Описание

| Код до объявления | Результат |
|---|---|
| `var x; console.log(x)` | `undefined` |
| `let x; console.log(x)` | TDZ до строки `let` |
| `function f(){}`; `f()` | работает |
| `const f = () => {}`; `f()` | TDZ до присваивания |

```js
console.log(count); // undefined
var count = 1;

// Эквивалентная модель:
var total;
console.log(total);
total = 1;
```

```js
console.log(name); // ReferenceError
const name = 'Анна';
```

Не создавайте неявные глобальные переменные присваиванием без объявления: в строгом режиме это ошибка, а в старом нестрогом коде — источник трудноуловимых багов.
