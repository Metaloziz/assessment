# 1. Тема

**Цепочка областей видимости**

---

# 2. Главное в одну фразу

Когда JavaScript встречает имя, он ищет его изнутри наружу по лексической цепочке до глобальной области.

---

# 3. Суть

> Имя находится в ближайшей подходящей области видимости; одноимённая локальная переменная перекрывает внешнюю. Если имя не найдено, чтение завершится `ReferenceError`.

---

# 4. Самое главное запомнить

- Цепочка строится по месту объявления, не по стеку вызовов.
- Внутренняя переменная с тем же именем скрывает внешнюю.
- `let` и `const` имеют блочную область, `var` — функциональную.
- Обращение к `let`/`const` до инициализации попадает в TDZ и бросает `ReferenceError`.
- Необъявленную переменную в строгом режиме нельзя создать присваиванием.

---

# 5. Описание

```js
const name = 'глобальная';

function outer() {
  const name = 'внешняя';

  function inner() {
    const name = 'внутренняя';
    return name;
  }

  return inner();
}

console.log(outer()); // внутренняя
```

Поиск `name` в `inner` заканчивается сразу: ближайшее собственное имя имеет приоритет. Если убрать его, будет найдено имя из `outer`, затем — глобальное.

```js
if (true) {
  var fromFunction = 1;
  let fromBlock = 2;
}

console.log(fromFunction); // 1
console.log(fromBlock); // ReferenceError
```

| Объявление | Область | До строки объявления |
| --- | --- | --- |
| `var` | Функция или глобальная | Есть имя со значением `undefined` |
| `let` | Блок | TDZ, доступ запрещён |
| `const` | Блок | TDZ, затем обязательна инициализация |

Глобальный `let` не обязан становиться свойством `window`; не следует опираться на `window` как на модель глобальной области. Сокращайте глубину вложенности и избегайте одинаковых имён там, где это ухудшает читаемость.
