# 1. Тема

**Preload, prefetch, async, defer**

---

# 2. Главное в одну фразу

`preload`/`prefetch` подсказывают браузеру, что грузить заранее, а `async`/`defer` управляют тем, когда выполняется `<script>` относительно парсинга HTML.

---

# 3. Ответ для собеседования

> «**Preload** (`<link rel="preload">`) — «скачай сейчас, это критично для текущей страницы»: шрифты, LCP-картинка, критический CSS/JS. Нужен `as="…"`.
>
> **Prefetch** (`<link rel="prefetch">`) — низкий приоритет: ресурс вероятно понадобится на **следующей** навигации.
>
> Для скриптов:
> - **async** — грузится параллельно парсингу и **выполняется сразу после загрузки** (порядок не гарантирован);
> - **defer** — тоже грузится параллельно, но **выполняется после разбора DOM**, в порядке появления в документе.
>
> Правило: критичный ресурс текущей страницы → preload; вероятный следующий маршрут → prefetch; аналитика/виджеты → async; app-бандл, зависящий от DOM → defer.»

---

# 4. Самое главное запомнить

- preload = сейчас, критично.
- prefetch = потом, низкий приоритет.
- async = выполнить как загрузился (порядок loose).
- defer = после DOM, порядок сохранён.

### Preload

```html
<link rel="preload" href="critical.css" as="style" />
```

### Prefetch

Предзагрузка ресурсов для следующих навигаций.

### async / defer

Атрибуты `<script>`: async выполняет сразу после загрузки; defer — после полного разбора DOM.

---

# 5. Описание

Preload, prefetch, async, defer — атрибуты для оптимизации загрузки ресурсов в HTML.

| Подсказка | Приоритет | Когда |
|-----------|-----------|-------|
| preload | высокий | текущая страница |
| prefetch | низкий | следующая навигация |
| async | — | независимый скрипт |
| defer | — | скрипт после DOM |
