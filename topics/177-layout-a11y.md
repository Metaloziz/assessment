# 1. Тема

**Доступность (aria, tabindex & etc.)**

---

# 2. Главное в одну фразу

Сначала обычные теги и видимый фокус, потом точечный ARIA — так Tab и скринридер видят те же действия, что мышь.

---

# 3. Суть

> Доступность на фронте — это тот же экран, которым можно пользоваться без мыши. Tab ходит по полям и кнопкам, скринридер произносит имя («Сохранить», «Закрыть»), кольцо фокуса показывает, где вы сейчас. Если этого нет, часть людей просто не дойдёт до действия.

> Типичный сбой выглядит «всё работает»: `<div onClick>` открывает форму с мыши и молчит для клавиатуры. Браузер держит второе дерево — **дерево доступности**: у узла роль, имя и состояние. Его собирают из HTML; атрибуты ARIA (`role`, `aria-*`) подкручивают, когда своего тега не хватает.

> Рабочий путь короткий. Берут `button`, ссылку с `href`, `input` с `<label>` — роль и Tab уже есть. Имя берётся из текста, подписи или `aria-label` на иконке. В порядок Tab попадают обычные контролы; `tabindex="-1"` нужен, чтобы поставить фокус из скрипта (например, в диалог). ARIA оставляют виджетам вроде вкладок и живого статуса, а не «рисуют» кнопку дивом с десятью атрибутами.

> Ловушка: `tabindex="1"` (и любой больше нуля) выдёргивает элемент из потока всей страницы. Снятый `outline` без своего `:focus-visible` оставляет клавиатуру без ориентира. Лишняя роль на уже семантичном теге путает сильнее, чем её отсутствие.

---

# 4. Самое главное запомнить

- Сначала HTML: `button`, `a href`, `label` + поле; ARIA — когда натива не хватает.
- Имя для скринридера: видимый текст, `<label>`, `aria-label` / `aria-labelledby` (у картинки — `alt`).
- `tabindex="0"` — в обычный порядок Tab; `-1` — только из скрипта; больше нуля — почти всегда ошибка.
- Убрали стандартный контур — обязаны дать своё кольцо через `:focus-visible`.
- `div` + `onClick` без роли, Tab и имени — интерфейс только для мыши.
- Не ставить `role="button"` на настоящий `<button>`: дубль роли не помогает.

---

# 5. Описание

```text
  мышь / Tab / скринридер
           │
           ▼
   HTML  →  дерево доступности  →  фокус и голос
           │
           ├─ роль     (кнопка, ссылка, поле)
           ├─ имя      (что произнести)
           └─ состояние (выключено, раскрыто)
```

## Сначала тег, не декорация

Мышь кликает по картинке. Tab и скринридер спрашивают другое: это кнопка? как её зовут? Можно ли на неё встать?

Нативный контрол отвечает сам. `<button>` уже в порядке Tab, жмётся Space и Enter, звучит как кнопка. Ссылка с `href` — как ссылка. Поле с `<label for>` получает имя из подписи, а не из `placeholder` (плейсхолдер исчезает, когда начали печатать).

| Нужно | Берите | Избегайте |
| --- | --- | --- |
| Действие | `<button>` | `<div onclick>` |
| Переход | `<a href>` | `<span onclick>` |
| Поле | `<input>` + `<label>` | только `placeholder` |

Кастомный виджет начинают с ближайшего тега, а не с пустого `div` и длинного ARIA.

## `tabindex`

Порядок Tab в документе совпадает с порядком в разметке — пока его не ломают.

`tabindex="0"` ставит в этот естественный ряд элемент, который сам по себе не фокусируется (редко нужно: лучше дать ему настоящий тег). `tabindex="-1"` Tab пропускает, но `element.focus()` сработает — так открывают модалку: фокус на контейнер или на первый контрол внутри, Esc закрывает, Tab не уходит «за штору».

Любое значение **больше нуля** — свой приоритет: браузер сначала обходит все «единицы», «двойки», и только потом обычные кнопки. Человек жмёт Tab и прыгает в неожиданное место. Почти всегда это баг, не приём.

## ARIA — точечно

ARIA не заменяет HTML. Она говорит дереву доступности то, чего тег не умеет.

Иконка-кнопка без текста немая: добавляют `aria-label="Закрыть"`, а саму картинку прячут `aria-hidden="true"`, чтобы имя не дублировалось. Раскрывашка сообщает `aria-expanded`. Сообщение «сохранено» без перевода фокуса — живой регион `aria-live`. Диалог — лучше нативный `<dialog>`; если рисуете сами, нужны роль, подпись и ловушка фокуса.

Правило проверки: сначала убрать ARIA и посмотреть, что даёт сам тег. Если кнопка уже кнопка, `role="button"` не нужен. Неверная роль хуже отсутствия: скринридер врёт.

## Видимый фокус

Кольцо вокруг контрола — не «уродство макета», а курсор для клавиатуры. Если его снять и не вернуть, Tab формально ходит, а глаз потерялся.

```css
/* плохо */
.button { outline: none; }

/* своё кольцо только для клавиатуры */
.button:focus-visible {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
}
```

`:focus-visible` обычно показывает контур после Tab и не рисует его после клика мышью.

## Ловушки

- Меню только по ховеру: с клавиатуры не открыть и не закрыть Esc.
- `aria-label` расходится с тем, что видно на кнопке.
- Фокус заперт в виджете, выйти Tab или Esc нельзя.
- Слабый контраст текста: скринридер тут не поможет — глаз тоже должен прочитать.
