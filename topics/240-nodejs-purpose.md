# 1. Тема

**Node.js, зачем нужен**

---

# 2. Главное в одну фразу

Node.js — рантайм JavaScript вне браузера: на нём пишут серверы, CLI, сборщики и скрипты, используя один язык и экосистему `npm`.

---

# 3. Суть

> Node.js — это не «новый язык», а среда исполнения JavaScript на машине: движок V8 плюс слой для файлов, сети, процессов и модулей. Код запускают командой `node`, без вкладки браузера и без DOM.
>
> Зачем это нужно: один язык закрывает фронт, бэкенд-API, dev-инструменты (webpack, Vite, ESLint, тесты) и служебные скрипты. Не нужно переключать стек только чтобы прочитать файл, поднять HTTP-сервер или прогнать сборку. Пакеты ставят через `npm` / `npx` — тот же экосистемный круг, что и у фронта.
>
> Как устроено: ввод-вывод (диск, сокеты) в основном неблокирующий — пока ждём сеть или файл, цикл событий (`event loop`) обслуживает другие задачи. Для типичных I/O-нагрузок одного процесса часто хватает; тяжёлую CPU-работу выносят в отдельные процессы или worker threads.
>
> Ловушка: Node не заменяет любой бэкенд «магией JS». Это не браузер (нет `window` / DOM), и не серебряная пуля для CPU-bound задач. Смысл — удобный рантайм там, где нужен JS на сервере или в тулчейне, а не «переписать всё на Node».

---

# 4. Самое главное запомнить

- Node.js = JS **вне браузера** (V8 + системные API), не фреймворк и не язык.
- Типичные роли: HTTP API, realtime, CLI, сборка/линт/тесты, автоматизация.
- Неблокирующий I/O и `event loop` — сильная сторона для многих сетевых и дисковых задач.
- `npm` / `package.json` — способ ставить и запускать инструменты и зависимости.
- В Node нет DOM; браузерные API доступны только если их явно эмулируют.
- CPU-тяжёлое лучше выносить из главного потока (воркеры / отдельные процессы), а не «крутить цикл» в обработчике запроса.

# 5. Описание

```text
Браузер                         Node.js
────────                        ───────
JS + DOM + Web APIs             JS (V8) + fs / net / process / …
вкладка пользователя            процесс на сервере / в CI / на ноутбуке
```

## Зачем появился и где живёт

До Node JavaScript почти целиком жил в браузере. Сервер писали на других языках, а сборку и скрипты — на bash, Python, Java и т.д. Node дал **тот же язык** доступ к файловой системе, сокетам и процессам ОС.

На практике фронтендер чаще всего встречает Node так:

| Роль | Пример |
|---|---|
| Dev-сервер и сборка | Vite, webpack, `npm run build` |
| Качество кода | ESLint, Prettier, Jest / Vitest |
| Скрипты проекта | генерация, миграции, `node scripts/…` |
| Backend / BFF | Express, Fastify, Nest — HTTP API рядом с фронтом |
| CLI | `npx`, свои утилиты на Node |

## Минимальный запуск

```bash
node app.js
```

```js
// app.js — без браузера, без DOM
const http = require('node:http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('ok');
});

server.listen(3000); // ← процесс слушает порт ОС
```

Тот же язык, что на фронте, но окружение другое: есть `process`, `Buffer`, модули `fs` / `http`; нет `document`.

## Неблокирующий I/O — зачем про него помнить

```text
запрос A ──► ждать БД ──┐
запрос B ──► ждать файл ├──► event loop переключает ожидания
запрос C ──► ответ сразу ┘     (пока A/B «висят» на I/O)
```

Пока один запрос ждёт диск или сеть, процесс может принимать другие. Это удобно для API и прокси. Если в обработчике крутить тяжёлый синхронный расчёт секундами — event loop блокируется, и «быстрый I/O» уже не помогает (этим займутся следующие темы про воркеры).

## Чем Node не является

- Не «замена браузеру» — UI в браузере по-прежнему на Web API.
- Не обязательный выбор любого бэкенда — язык и модель нагрузки должны подходить задаче.
- Не бесконечная многопоточность «из коробки» для CPU: модель заточена под I/O и много ожиданий.

Соседние темы группы разбирают плюсы/минусы для фронтовых приложений, модули/`process`, роутинг и дальше — уже практику сервера.
