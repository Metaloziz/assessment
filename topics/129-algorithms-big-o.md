# 1. Тема

**Уровни Big O нотации и оценка сложности алгоритма**

---

# 2. Главное в одну фразу

Big O описывает, как растёт время или память алгоритма при увеличении входа, отбрасывая константы и фокусируясь на доминирующем члене.

---

# 3. Суть

> Big O — язык «насколько плохо будет при большом n». Говорят не «заняло 12 мс на моём ноутбуке», а «число шагов растёт как квадрат размера входа» — O(n²). Константы и младшие слагаемые отбрасывают: 3n² + 100n и n² в одной «корзине» при огромном n.
>
> На собеседовании и в код-ревью хватает шкалы: O(1), O(log n), O(n), O(n log n), O(n²), иногда O(2ⁿ). Линейный проход массива — O(n); бинпоиск по отсортированному — O(log n); двойной цикл по n — обычно O(n²).
>
> Оценивают **худший** типичный случай (worst-case), отдельно смотрят память. Big O не заменяет профилировщик: плохая константа или I/O могут убить «асимптотически хороший» код на реальных данных.

---

# 4. Самое главное запомнить

- Big O = **рост** при n → ∞, не абсолютное время на одном замере.
- Игнорируют константы и младшие члены: O(2n + 50) → **O(n)**.
- Частые уровни: **O(1)** · **O(log n)** · **O(n)** · **O(n log n)** · **O(n²)**.
- Вложенный цикл по n×n → подозревайте **O(n²)**.
- `Map`/`объект` lookup в среднем ≈ **O(1)**; `includes`/`find` по массиву — **O(n)**.
- Считайте и **память** (extra space), не только CPU.
- Best / average / worst — разные истории; на собесе чаще спрашивают worst-case.

---

# 5. Описание

## Шкала «от дешёвого к дорогому»

```text
O(1)  <  O(log n)  <  O(n)  <  O(n log n)  <  O(n²)  <  O(2ⁿ) …
```

| Класс | Интуиция | Пример в JS |
|-------|----------|-------------|
| O(1) | Шагов почти не зависит от n | `arr[i]`, `map.get(key)` |
| O(log n) | Каждый шаг сильно сужает область | Бинарный поиск |
| O(n) | Один проход | `for…of`, `.map` один раз |
| O(n log n) | «Умно-отсортировать» | Типичная хорошая сортировка |
| O(n²) | Для каждого — ещё проход по всем | Двойной цикл, наивная проверка пар |
| O(2ⁿ) | Взрыв вариантов | Наивный перебор подмножеств |

## Как читать код

```javascript
// O(n) — один проход
function sum(arr) {
  let s = 0;
  for (const x of arr) s += x;
  return s;
}

// O(n²) — для каждого i снова идём по массиву
function hasPairSumNaive(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === target) return true;
    }
  }
  return false;
}

// O(n) время, O(n) память — Set для дополнения
function hasPairSum(arr, target) {
  const seen = new Set();
  for (const x of arr) {
    if (seen.has(target - x)) return true;
    seen.add(x);
  }
  return false;
}
```

Правило большого пальца:

1. Найти цикл / рекурсию — источник роста.
2. Вложенность независимых проходов по n → перемножить.
3. Поиск внутри цикла по тому же массиву → часто n².
4. Замена поиска на `Set`/`Map` → часто снять один множитель n.

## Что Big O не говорит

- Точные миллисекунды на вашем CPU.
- Стоимость констант (тяжёлая операция внутри O(n) может быть медленнее лёгкой O(n²) на маленьком n).
- Скрытый I/O, layout thrashing в DOM, сетевые задержки.

Поэтому: оценка → гипотеза → замер на реалистичном n.

## Типичные вопросы на собеседовании

- Что такое Big O? — Асимптотический рост стоимости при увеличении входа.
- Сложность этого цикла? — Уметь объяснить вслух по коду.
- Чем O(n) лучше O(n²)? — На больших n квадрат растёт заметно быстрее.
- Зачем память в оценке? — Иногда ускоряем время ценой дополнительной структуры (trade-off).
