# 1. Тема

**Наследование классов**

---

# 2. Главное в одну фразу

`extends` строит прототипную связь между классами, а `super` вызывает конструктор или метод родительского класса.

---

# 3. Суть

> Наследование классов нужно, когда дочерняя сущность действительно является частным случаем родительской и сохраняет его контракт. `extends` связывает прототипы, поэтому экземпляр наследника находит методы родителя по цепочке.
>
> Это удобно, когда нескольким близким сущностям нужны общие поля и поведение: например, базовая проверка или форматирование. Родительский класс задаёт общую часть, а наследник добавляет детали или уточняет метод.
>
> В конструкторе наследника сначала вызывают `super()`: он создаёт и инициализирует `this` через родительский конструктор. Метод можно переопределить, а общую часть вызвать через `super.method()`. `instanceof` учитывает всю такую цепочку.
>
> Не стоит строить наследование только ради повторного использования. Если объект не является видом базового, а лишь использует его поведение, проще передать зависимость или собрать объект из частей.

---

# 4. Самое главное запомнить

- В derived constructor нельзя читать или писать `this` до `super()`.
- `super()` вызывает родительский конструктор.
- `super.method()` вызывает метод родительского прототипа.
- `instanceof` учитывает цепочку наследования.
- JavaScript поддерживает одиночное наследование классов; для переиспользования часто подходит композиция.

---

# 5. Описание

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} издаёт звук`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }

  speak() {
    return `${super.speak()}: гав`;
  }
}
```

| Конструкция | Назначение |
|---|---|
| `class Dog extends Animal` | наследует экземплярные и статические возможности |
| `super(name)` | вызывает конструктор `Animal` |
| `super.speak()` | обращается к реализации родителя |
| `dog instanceof Animal` | проверяет цепочку прототипов |

Методы классов живут в прототипах, а поля экземпляра создаются отдельно для каждого объекта. Не стройте глубокие иерархии только ради переиспользования: если объект «имеет» поведение, а не «является» видом другого, лучше передать зависимость или использовать отдельную функцию.
