# 1. Тема

**Лексическое окружение**

---

# 2. Главное в одну фразу

Лексическое окружение — «словарь» имён текущего блока кода плюс ссылка наружу; по этой цепочке движок ищет переменные там, где функция была написана, а не где её вызвали.

---

# 3. Суть

> Лексическое окружение — внутренняя структура JavaScript: для каждого выполняемого блока или вызова функции движок держит таблицу локальных имён и ссылку на внешнее окружение. «Лексическое» значит, что связи задаются текстом программы при объявлении, а не местом вызова.
>
> Без этого не было бы предсказуемого scope и замыканий: внутренняя функция могла бы «видеть» чужие локальные переменные вызывающего кода или терять доступ к переменным родителя после его завершения. На практике это объясняет, почему колбэк помнит `count` из фабрики и почему `this` у стрелочной функции берётся снаружи.
>
> Поиск имени идёт от текущего окружения наружу по цепочке. Каждый вызов функции создаёт своё окружение; замыкание хранит ссылку на переменную, а не снимок значения. Ловушка: путать лексическое окружение с `this` — это разные механизмы.

---

# 4. Самое главное запомнить

- Лексическое окружение = локальные имена + ссылка на внешнее окружение.
- Связи фиксируются при объявлении функции (по тексту кода), не при вызове.
- Поиск переменной: сначала своё окружение, потом наружу по цепочке.
- Каждый вызов функции создаёт новое окружение; несколько замыканий могут жить независимо.
- Замыкание держит ссылку на переменную; `this` к лексическому окружению не относится (кроме стрелок, где `this` не свой).
- `let`/`const` в цикле дают отдельное окружение на итерацию — отсюда разное поведение с `var`.

---

# 5. Описание

## Минимальный пример замыкания

```js
function makeCounter() {
  let count = 0;

  return () => ++count;
}

const first = makeCounter();
console.log(first()); // 1
console.log(first()); // 2

const second = makeCounter();
console.log(second()); // 1 — своё окружение, свой count
```

После завершения `makeCounter` переменная `count` жива, пока жива возвращённая функция: на окружение всё ещё есть ссылка.

## Почему важен момент объявления

```js
let x = 1;

function outer() {
  let x = 2;
  return function inner() {
    return x;
  };
}

const f = outer();
console.log(f()); // 2 — inner смотрит в окружение outer, не в глобальное на момент вызова
```

Вызов `f()` снаружи не подставляет глобальный `x`: цепочка окружений уже зафиксирована.

## `var` vs `let` в цикле

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3 — одно окружение на цикл
}

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0, 1, 2 — окружение на каждую итерацию
}
```

## Словарь

| Понятие | Значение |
| --- | --- |
| Лексическое окружение | Имена текущей области + ссылка наружу |
| Внешнее окружение | Область, в которой функция была объявлена |
| Замыкание | Функция вместе с доступом к внешним переменным по этой цепочке |
| Scope chain | Цепочка окружений при поиске имени |

Не стоит считать замыкание автоматической утечкой памяти: память удерживается, пока на функцию есть достижимая ссылка. Утечка — когда долгоживущий обработчик держит большой ненужный объект через замыкание.
