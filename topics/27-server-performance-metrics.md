# 1. Тема

**Метрики серверной производительности**

---

# 2. Главное в одну фразу

Серверные метрики показывают, насколько эффективно backend и инфраструктура обрабатывают запросы: скорость ответа, пропускная способность, ресурсы, ошибки и доступность.

---

# 3. Ответ для собеседования

> «Клиентские метрики — про UX в браузере; **серверные** — про backend и инфра.
>
> Ключевые:
> - **Response Time** — время обработки запроса (бизнес-логика + БД);
> - **Throughput** — успешные запросы в единицу времени (RPS);
> - **Resource usage** — CPU, memory, I/O;
> - **Error rate** — доля ошибочных ответов;
> - **Uptime** — доступность;
> - **Connection handling** — одновременные подключения.
>
> Смотрят через APM, realtime-логи/метрики и нагрузочные тесты.
> Для фронта важно: высокий TTFB часто = медленный/перегруженный backend, а не «тяжёлый React».»

---

# 4. Самое главное запомнить

- Response time ≠ только сеть — включает логику и БД.
- Throughput = RPS.
- CPU / Memory / I/O — ресурсы.
- Error rate + uptime — здоровье сервиса.
- APM + load tests + метрики/логи.

### Ключевые метрики

- **Время отклика** — обработка запроса сервером (логика + БД).
- **Пропускная способность** — RPS.
- **Использование ресурсов** — CPU, Memory, I/O.

### Дополнительно

- Error Rate, Uptime, Connection handling.

### Мониторинг

APM, логи и метрики в реальном времени, нагрузочное тестирование.

---

# 5. Описание

Метрики серверной производительности — показатели эффективности backend-систем и инфраструктуры.

| Метрика | Что отвечает |
|---------|--------------|
| Response time | Как быстро ответил сервер? |
| Throughput | Сколько выдерживает? |
| CPU / Memory / I/O | Хватает ли ресурсов? |
| Error rate | Как часто падает? |
| Uptime | Насколько доступен? |
