# 1. Тема

**Механизмы уменьшения бандла и роль CDN**

---

# 2. Главное в одну фразу

Размер бандла режут на сборке, а CDN ускоряет доставку уже собранных файлов через край сети — логику приложения он не уменьшает.

---

# 3. Суть

> Бандл — JS (и часто CSS), который сборщик собрал из исходников для браузера. Размер режут **на сборке**: tree shaking выкидывает неиспользуемые ESM-экспорты, code splitting (`import()`) уносит редкие маршруты в отдельные чанки, minify укорачивает имена и пробелы, а тяжёлые зависимости не тащат целиком (moment со всеми локалями, lodash через `import _`). После `build` файл всё ещё нужно доставить. **CDN** — геораспределённый кэш у края сети: он не выкидывает мёртвый код, а отдаёт уже готовый ассет ближе к пользователю.
>
> Зачем оба рычага вместе: на слабом устройстве парсинг и выполнение большого JS часто дороже, чем «просто скачать». Маленький initial chunk быстрее становится интерактивным; gzip/brotli и edge-кеш режут время доставки того, что осталось. Один minify без splitting оставляет админку в первом экране; CDN поверх жирного бандла ускоряет скачивание, но не парсинг.
>
> Как стыкуется на проде. Сборка пишет файлы с `contenthash` в имени. `index.html` кешируют коротко (или `no-cache`), чтобы браузер узнал новые имена чанков. Сами чанки — с длинным `Cache-Control` и `immutable`: пока имя не сменилось, edge и браузер не ходят на origin. Карту «кто съел килобайты» смотрят analyzer’ом *до* настройки CDN.
>
> Ловушка: minify ≠ сжатие на проводе. Terser режет исходник; brotli сжимает байты ответа. CDN не чинит два React в чанке и не заменяет shaking. «Вечный» кеш без хеша в имени залипает на старой версии.

---

# 4. Самое главное запомнить

- Tree shaking работает на ESM и подсказке `sideEffects`; CJS и побочные эффекты на `import` оставляют мёртвый код в чанке.
- Code splitting (`import()` / `React.lazy`) режет **начальный** бандл, не суммарный вес всех маршрутов.
- Minify (Terser/esbuild) ≠ gzip/brotli: сначала короче исходник, потом меньше байт на проводе.
- CDN = доставка и кеш у края; дубли библиотек и невытрясенный lodash он не выкинет.
- Хеш в имени (`contenthash`) + `Cache-Control: public, max-age=…, immutable` для чанков; `index.html` — короткий кеш или revalidate.
- Сначала analyzer (что в чанке), потом оптимизация и CDN.

# 5. Описание

```text
исходники (ESM)
    │  tree shaking · splitting · minify · не тащить тяжёлые deps
    ▼
dist/app.[contenthash].js          ← артефакт сборки
    │
    ▼
CDN edge  (gzip/brotli, Cache-Control)
    │
    ├─ hashed chunk  → долгий кеш, immutable
    └─ index.html    → короткий кеш / revalidate
         │
         ▼
      браузер
```

Сборка отвечает за *сколько кода* уедет. CDN — за *как быстро* этот файл доедет и как долго его можно не качать снова.

## Что режет размер на сборке

Три разных слоя, их путают:

| Слой | Что делает | Что не делает |
|------|------------|----------------|
| Tree shaking | Выкидывает неиспользуемые ESM-экспорты | Не чинит CJS и side effects на import |
| Code splitting | Режет **первый** чанк: редкое — отдельным файлом | Не уменьшает сумму всех маршрутов |
| Minify | Короче имена, меньше whitespace, dead code внутри файла | Не заменяет gzip/brotli на CDN |

```js
// utils.js — в prod `dead` может исчезнуть из чанка
export function used() { return 1; }
export function dead() { return 2; }

// index.js
import { used } from './utils';
```

Тяжёлые зависимости часто важнее, чем ещё один проход Terser: `moment` со всеми локалями, иконки целиком, lodash через `import _ from 'lodash'`. Analyzer (webpack-bundle-analyzer, Statoscope) показывает состав чанка — без этой картины оптимизация наугад.

Соседние темы: как именно настроить shaking и Terser в webpack — в группе «Сборка»; здесь важен **эффект на вес** и стык с доставкой.

## Code splitting и начальный бандл

Динамический `import()` (в React — `lazy` + `Suspense`) создаёт отдельный чанк. Маршрут `/admin` не должен лежать в JS первой отрисовки главной.

```js
const Admin = lazy(() => import('./Admin'));
```

Это ускоряет старт, а не «приложение стало меньше на диске». Пользователь админки всё равно скачает свой чанк — позже.

## CDN: доставка, не логика

CDN (Content Delivery Network) держит копии статики на узлах ближе к пользователю. Запрос к `cdn.example.com/app.a1b2.js` часто закрывается с ближайшего edge, без кругосветки до origin.

CDN **не** анализирует `import` и не выкидывает функции. Он кеширует байты, которые выложили. Жирный бандл на CDN — тот же жирный бандл, только скачивается чуть быстрее.

Отдельно: вынести React на публичный CDN через `externals` — это «не бандлить библиотеку, надеясь на общий кеш браузера». На практике HTTP/2 и свои hashed vendor-чанки часто предсказуемее, чем чужой `unpkg`.

## Кеш: HTML короткий, чанки длинные

Имя с хешем содержимого — ключ инвалидации. Сменился код → другое имя файла → старый URL больше не просят.

```http
Cache-Control: public, max-age=31536000, immutable
```

Так отвечают на `app.[contenthash].js`. `immutable` говорит браузеру не перепроверять файл, пока живёт URL.

`index.html` так кешировать нельзя: в нём ссылки на текущие имена чанков. Его отдают с коротким `max-age` или `no-cache` + `ETag` / `If-None-Match` (304, если HTML не менялся).

Типичный провал: длинный кеш на `/app.js` без хеша — выкатили фикс, пользователи неделю сидят на старом файле.

## Сжатие на проводе

Edge (или origin) может отдать `Content-Encoding: br` или `gzip`. Браузер просит это через `Accept-Encoding`. Размер в Network — уже сжатый; analyzer показывает uncompressed.

Порядок: сначала меньше логики (shake / split / minify / зависимости), потом сжатие и CDN. Brotli по живому невытрясенному lodash сэкономит байты на проводе, но не время на parse/compile.

## Что не путать

- **CDN ≠ уменьшение бандла.** Меньше кода — сборка; быстрее доставка — CDN и сжатие.
- **Minify ≠ gzip.** Разные этапы, разные цифры в отчётах.
- **Splitting ≠ меньше JS в продукте.** Меньше на *первом* экране.
- Сначала карта чанка, потом CDN. Кешировать мусор с края — всё ещё мусор, только ближе.
