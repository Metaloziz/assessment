# 1. Тема

**Динамическое программирование:** подзадачи · мемоизация · таблица · оптимальность

---

# 2. Главное в одну фразу

Динамическое программирование (DP) решает задачу, запоминая ответы на пересекающиеся подзадачи — вместо экспоненциального пересчёта получается полиномиальное заполнение таблицы или кэша.

---

# 3. Суть

> Динамическое программирование — способ считать ответ из ответов на **меньшие подзадачи**, если они **перекрываются** и из них собирается оптимальное (или однозначное) решение целого. Классика: числа Фибоначчи, пути в сетке, рюкзак, размен монет.
>
> Наивная рекурсия без памяти пересчитывает одно и то же снова и снова — часто O(2ⁿ). **Мемоизация** (top-down) кладёт результат в кэш при первом вычислении. **Табуляция** (bottom-up) явно заполняет массив/таблицу от базы к цели. Сложность обычно O(число состояний × работа на переход).
>
> DP уместен, когда есть оптимальная подструктура и перекрывающиеся подзадачи. Если подзадачи не пересекаются — это скорее «разделяй и властвуй» (как Merge Sort), а не DP. Ловушка: неправильно выбранное состояние или переход даёт верный код на маленьких тестах и ломается на краевых.

---

# 4. Самое главное запомнить

- Два условия: **перекрывающиеся подзадачи** + способ собрать ответ из меньших (часто оптимальная подструктура).
- **Top-down** = рекурсия + `Map`/`массив`-кэш (мемоизация).
- **Bottom-up** = цикл, явно заполняем `dp[]` / `dp[][]` от базы.
- Число состояний × цена перехода ≈ оценка времени; размер таблицы ≈ память.
- Фибоначчи без кэша — дерево вызовов; с DP — линейный проход.
- Не путать с жадным алгоритмом: greedy берёт локально лучший шаг без гарантии, что все подзадачи учтены как в DP.
- Сначала сформулируйте **состояние** (`dp[i]` = …) и **переход**, потом пишите код.

# 5. Описание

## Идея на пальцах

Задача дробится на куски. Куски повторяются. Ответ на кусок пишем один раз и переиспользуем.

```text
fib(5)
├─ fib(4)
│  ├─ fib(3)
│  │  ├─ fib(2)
│  │  └─ fib(1)
│  └─ fib(2)          ← уже считали
└─ fib(3)              ← уже считали
```

Без кэша `fib(3)` и `fib(2)` считаются многократно. С кэшем — один раз.

## Top-down (мемоизация)

```typescript
function fibMemo(n: number, memo = new Map<number, number>()): number {
  if (n <= 1) return n;
  const hit = memo.get(n);
  if (hit !== undefined) return hit;
  const value = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, value);
  return value;
}
```

Рекурсия описывает переход «как в формуле»; кэш убирает повторную работу.

## Bottom-up (таблица)

```typescript
function fibTable(n: number): number {
  if (n <= 1) return n;
  const dp = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1]! + dp[i - 2]!;
  }
  return dp[n]!;
}
```

Часто достаточно двух переменных вместо массива — O(1) доп. памяти, если нужны только предыдущие состояния.

## Ещё один канон: лестница

`ways(n)` — число способов подняться на `n` ступеней, шагая на 1 или 2.

- База: `ways(0) = 1`, `ways(1) = 1` (или `ways(1) = 1`, `ways(2) = 2` — зафиксируйте соглашение).
- Переход: `ways(i) = ways(i - 1) + ways(i - 2)`.

Та же схема, что у Фибоначчи: другое «что означает состояние».

## Размен монет (количество способов)

Даны номиналы `coins` и сумма `amount`. `dp[x]` — число способов набрать сумму `x`.

```typescript
function changeWays(amount: number, coins: number[]): number {
  const dp = Array(amount + 1).fill(0);
  dp[0] = 1;
  for (const c of coins) {
    for (let x = c; x <= amount; x++) {
      dp[x] += dp[x - c]!;
    }
  }
  return dp[amount]!;
}
```

Порядок циклов важен: монеты снаружи дают комбинации (порядок номиналов не различает перестановки).

## Как подходить к новой задаче

1. Что является **состоянием**? (индекс, остаток суммы, маска…)
2. Какой **ответ** хранится в ячейке? (число способов, минимум шагов, да/нет…)
3. Откуда **переход**? Из каких меньших состояний?
4. Какие **базы**? Что на краях?
5. Top-down или bottom-up — что проще отладить на ваших данных?

## Типичные ловушки

- Забыли базу → мусор или бесконечная рекурсия.
- Состояние слишком грубое → «оптимум» неверный.
- Путают минимум монет и число способов — разные переходы.
- Считают DP там, где хватает жадного или одного прохода.

## Связь с Big O

| Подход | Типичное время для fib(n) | Память |
|--------|---------------------------|--------|
| Наивная рекурсия | O(2ⁿ) | O(n) стек |
| Memo / table | O(n) | O(n) или O(1) |
