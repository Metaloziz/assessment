# 1. Тема
**Стабы**
---
# 2. Главное в одну фразу
Стаб — тестовый двойник с заранее заданным ответом: он управляет входными данными зависимости, чтобы проверить состояние или результат тестируемого кода.
---
# 3. Ответ для собеседования
> «Стаб подменяет зависимость фиксированными данными: например, репозиторий возвращает пользователя, а HTTP-клиент — заранее подготовленный ответ. В тесте со стабом фокус на результате системы. Мок отличается целью: он проверяет взаимодействие, например что после регистрации был вызван email-сервис с нужными параметрами. В Jest один `jest.fn()` технически может быть и стабом, и моком — различие семантическое, в том, что именно доказывает тест.»
---
# 4. Самое главное запомнить
- Стаб контролирует данные от зависимости.
- Мок проверяет коммуникацию с зависимостью.
- Стаб не должен реализовывать бизнес-логику реального сервиса.
- Проверяйте результат со стабом и вызов с моком.
---
# 5. Описание
| Аспект | Стаб | Мок |
|---|---|---|
| Основная цель | Дать предсказуемые данные | Проверить взаимодействие |
| Фокус | Состояние и результат | Вызов, аргументы, число вызовов |
| Типичный пример | `findById` вернул пользователя | `email.send` был вызван |

```javascript
// Стаб: контролируем данные, проверяем результат
test('возвращает имя найденного пользователя', () => {
  const repository = {
    findById: jest.fn().mockReturnValue({ id: 1, name: 'Анна' })
  };

  const result = new UserService(repository).getDisplayName(1);

  expect(result).toBe('Анна');
});
```

```javascript
// Мок: проверяем взаимодействие
test('после регистрации отправляет письмо', async () => {
  const mailer = { send: jest.fn().mockResolvedValue(undefined) };
  await new RegistrationService(mailer).register('anna@example.com');

  expect(mailer.send).toHaveBeenCalledWith('anna@example.com', 'Welcome!');
});
```

Стабируйте медленные, недетерминированные и внешние зависимости — API, БД, время, генераторы случайных значений. Интеграционные тесты отдельно должны подтверждать, что реальная интеграция тоже работает.
