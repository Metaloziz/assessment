# 1. Тема

**Сборщик мусора V8**

---

# 2. Главное в одну фразу

V8 освобождает память, когда объект больше недостижим от корней — стека, глобальных ссылок и активных контекстов, — а не потому что «он уже не нужен по смыслу».

---

# 3. Суть

> Сборщик мусора V8 смотрит на **достижимость**: если от корней нельзя дойти до объекта по живым ссылкам, его можно убрать. Движок не знает бизнес-логику — `session` «уже не нужна пользователю», но пока на неё указывает `Map`, кэш или замыкание, память не отпустит.
>
> Большинство новых объектов живут в **молодом поколении** (young generation): там быстрый **minor GC**. Пережившие несколько сборок переезжают в **старое** (old generation), где **major GC** дороже: mark → sweep → при необходимости compaction.
>
> Момент сборки не гарантирован — `session = null` лишь делает объект кандидатом. Чинят удерживаемые ссылки и темп аллокаций (**GC pressure**), а не «ручной вызов GC» в браузере.

---

# 4. Самое главное запомнить

- Объект может стать мусором, когда на него нет пути от корней; когда именно соберут — неизвестно.
- Minor GC обслуживает young generation; major GC — old, с более длинными паузами.
- Mark помечает живые объекты, sweep освобождает мёртвые, compaction уплотняет фрагментированную кучу.
- V8 часть работы делает инкрементально и конкурентно (Orinoco), но паузы на main thread возможны.
- Типичные утечки — безлимитный кэш, забытый listener, `setInterval`, замыкание с большим объектом.
- GC pressure — темп появления мусора; смотрят Performance / Memory / `--trace-gc`, снижают аллокации и отпускают ссылки.

---

# 5. Описание

```text
корни (stack · global · активные контексты)
        │
        ▼
   достижимые объекты ──► mark (живые)
        │
        ▼
   нет пути от корней ──► sweep (мусор) · compaction

young generation ──minor GC──► пережившие ──► old generation ──major GC──►
```

## Достижимость, не «нужность»

Сборщик не читает комментарии и требования. Объект жив, пока до него можно дойти от корней:

```js
let session = { payload: new Array(1_000_000) };
session = null; // ← кандидат на сборку; момент GC не определён
```

Пока ссылка жива — в heap объект **не мусор**, даже если UI его уже не показывает.

## Young и old generation

Новые объекты попадают в **young generation** (nursery). Там частый **minor GC**: быстро собирает короткоживущий «мусор» (временные строки, промежуточные массивы в цикле). Объекты, пережившие несколько minor GC, **продвигаются** (promotion) в **old generation**.

В old работает **major GC** тяжелее: mark-sweep по большому объёму, иногда compaction. Долгоживущие структуры (кэши, синглтоны, глобальные таблицы) скапливаются здесь — отсюда более заметные паузы при давлении памяти.

## Mark, sweep, compaction

1. **Mark** — обход от корней, пометка всего достижимого.
2. **Sweep** — освобождение непомеченного.
3. **Compaction** — сдвиг живых блоков, чтобы уменьшить «дыры» в куче (не на каждой сборке).

V8 (Orinoco) старается размазывать работу: инкрементальный mark, concurrent sweep, но main thread всё равно может подождать.

## GC pressure

**GC pressure** — не «сколько байт сейчас», а **как быстро** вы создаёте временные объекты. Много аллокаций в горячем цикле или на каждый кадр рендера → чаще minor GC; объекты, застрявшие в old → тяжелее major GC. В Performance видны полосы Garbage Collection; UI дёргается.

Снижают pressure:

- меньше лишних объектов в горячих путях (переиспользование буферов, без `map/filter` на каждый пиксель без нужды);
- отпускание долгоживущих ссылок (кэш с лимитом, снятие listeners).

## Утечки ссылок

```js
const cache = new Map();

function remember(key, value) {
  cache.set(key, value); // ← без TTL/LRU/delete — всё достижимо от global
}
```

**TTL** (Time To Live) — срок жизни записи: просроченные ключи удаляют по таймеру или при чтении.

**LRU** (Least Recently Used) — при переполнении выкидывают запись, к которой дольше всего не обращались.

Без лимита `Map` держит значения достижимыми — для GC это не мусор.

Другие частые ловушки:

```js
const huge = { data: new Array(5000).fill('x') };

function onTick() {
  console.log(huge.data.length); // ← замыкание держит huge
}
const id = setInterval(onTick, 1000);
// clearInterval(id) — иначе huge жив, пока жив interval
```

## Как смотреть в инструментах

- **Chrome DevTools → Performance**: запись сценария, полосы GC на Main thread, длительность пауз.
- **Memory**: heap snapshot до/после действия; retaining paths — кто держит объект.
- **Performance monitor**: график JS heap — «пила» при высоком pressure.
- **Node.js**: `--trace-gc` / `--trace-gc-verbose` — minor/major, объём и время в логе.

`performance.memory` в браузере — грубый ориентир (не стандарт везде), не замена трейсу GC.
