# 1. Тема

**Сборщик мусора V8**

---

# 2. Главное в одну фразу

V8 освобождает неиспользуемую память по достижимости объектов от корней, а не по счётчику «нужности».

---

# 3. Суть

> Сборщик мусора V8 освобождает объект, когда до него больше нельзя дойти от корней: стека, глобальных ссылок и активных контекстов. Он не знает бизнес-смысл данных и не удаляет объект только потому, что тот «уже не нужен».
>
> Это важно для долгоживущих приложений: безлимитный кэш, обработчик события или таймер могут удерживать большие данные и превращаться в утечку. Частые временные объекты также увеличивают нагрузку на память и паузы.
>
> V8 быстро собирает большинство объектов в молодом поколении, а пережившие несколько сборок переносит в старое, где работа дороже. Сначала движок помечает достижимые объекты, затем очищает память и при необходимости уплотняет её. Момент сборки не гарантирован, поэтому исправляют удерживаемые ссылки, а не пытаются вручную вызвать GC.

---

# 4. Самое главное запомнить

- Недостижимый объект может быть удалён, но момент сборки не определён.
- Minor GC обслуживает young generation; major GC маркирует и очищает старое поколение.
- Mark находит живые объекты, sweep освобождает мусор, compaction уменьшает фрагментацию.
- V8 выполняет часть работы инкрементально и конкурентно, но паузы возможны.
- Главные причины утечек — удерживаемые ссылки: безлимитные кэши, listeners, таймеры, замыкания.

---

# 5. Описание

```js
let session = { payload: new Array(1_000_000) };
session = null; // объект стал кандидатом на сборку
```

Сборщик запускается по давлению памяти и эвристикам, а не «каждые N секунд». Создание массы временных объектов повышает GC pressure; долгоживущий `Map` без лимита удерживает данные независимо от того, нужны ли они бизнес-логике.

```js
const cache = new Map();

function remember(key, value) {
  cache.set(key, value); // нужен TTL, LRU или явная очистка
}
```

Для диагностики в браузере используют DevTools Memory: сравнивают heap snapshots до и после сценария, ищут retaining paths. В Node.js `--trace-gc` помогает увидеть частоту и длительность сборок, но оптимизацию начинают с измерения, а не с ручного «вызова GC».
