# 1. Тема

**Производительность: прототип против замыкания**

---

# 2. Главное в одну фразу

Метод в прототипе разделяется всеми экземплярами, а метод-замыкание создаётся вместе с каждым экземпляром и удерживает собственный лексический контекст.

---

# 3. Суть

> Метод в прототипе существует в одном экземпляре и делится всеми объектами класса. Метод, созданный как замыкание в конструкторе, появляется заново при каждом `new` и хранит доступ к своему лексическому окружению.
>
> Для тысяч одинаковых моделей прототип обычно экономит память и делает структуру объектов проще. Замыкание оправдано, когда функции действительно нужно захватить приватные данные или отдельную конфигурацию.
>
> Прототипный метод находит состояние через `this`, а замыкание держит ссылки на использованные внешние переменные, пока жива функция. Скорость вызова нельзя предсказать одной формулой: JIT способен оптимизировать оба варианта. Выбор делают по модели данных, потребности в приватности и профилю памяти с CPU, а не по микробенчмарку.

---

# 4. Самое главное запомнить

- `Class.prototype.method` — одна функция для всех экземпляров.
- Метод, созданный в конструкторе, — отдельная функция на каждый `new`.
- Замыкание удерживает всё, на что ссылается из внешней области.
- Private fields `#field` часто дают инкапсуляцию без функций на экземпляр.
- Нельзя надёжно объявить «прототип всегда быстрее»: важны количество объектов и hot path.

---

# 5. Описание

```js
class ProtoCounter {
  #value = 0;

  increment() {
    return ++this.#value; // метод общий, состояние приватно
  }
}

function ClosureCounter() {
  let value = 0;
  this.increment = () => ++value; // новая функция и контекст
}
```

Прототипное свойство ищется по цепочке, но при стабильных shapes движок часто эффективно кэширует такой доступ. Замыкание даёт настоящую лексическую приватность, однако большие данные во внешней области остаются живы, пока жив callback.

В UI функция на экземпляр бывает оправдана, например, чтобы callback сохранил контекст или конфигурацию. Но для тысяч моделей/элементов лучше избегать неосознанного создания множества одинаковых closures. Проверяйте heap snapshot и CPU-профиль, а не микробенчмарк с одной версией V8.
