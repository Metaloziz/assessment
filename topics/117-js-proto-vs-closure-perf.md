# 1. Тема

**Производительность: прототип против замыкания** — общая функция на `prototype` · новая функция на каждый `new` · память · приватность · когда что выбирать

---

# 2. Главное в одну фразу

Метод на прототипе один на все экземпляры; метод-замыкание в конструкторе создаётся заново при каждом `new` и держит свой лексический контекст.

---

# 3. Суть

> Прототипный метод существует в одном экземпляре функции и делится всеми объектами класса. Замыкание, повешенное в конструкторе (`this.inc = () => …`), появляется при каждом `new` и может захватить внешние переменные.
>
> Для тысяч однотипных моделей прототип обычно экономит память и упрощает форму объектов. Замыкание оправдано, когда функции реально нужна лексическая приватность или своя конфигурация.
>
> Скорость вызова нельзя свести к «прототип всегда быстрее»: JIT оптимизирует оба пути. Смотрят на число экземпляров, удержание памяти замыканиями и CPU-профиль. Часто `#private` + метод на прототипе даёт инкапсуляцию без функции на каждый объект.

---

# 4. Самое главное запомнить

- `Class.prototype.method` — одна функция на всех.
- `this.method = () => …` в конструкторе — новая функция на каждый экземпляр.
- Замыкание удерживает всё, на что ссылается (риск утечек / раздутого heap).
- `#field` + метод прототипа — приватность без per-instance function.
- Выбор — по модели данных и профилю, не по микробенчмарку на одной версии V8.

---

# 5. Описание

## Два паттерна

```js
class ProtoCounter {
  #value = 0;
  increment() {
    return ++this.#value; // одна функция на Class.prototype
  }
}

function ClosureCounter() {
  let value = 0;
  this.increment = () => ++value; // новая функция + контекст на каждый new
}
```

```text
Proto:     [fn increment] ←── shared ── instance1, instance2, …
Closure:   instance1.increment → fn1 → env{value}
           instance2.increment → fn2 → env{value}
```

## Память

| | Прототип | Замыкание в конструкторе |
| --- | --- | --- |
| Функции | 1 на класс | N на N экземпляров |
| Состояние | на экземпляре / `#field` | в лексическом окружении |
| Риск | общий мутабельный state на prototype | удержание больших данных в closure |

## Когда замыкание ок

- Короткоживущие объекты, мало экземпляров.
- Нужен стабильный callback с захватом конфига без `bind`.
- Настоящая лексическая приватность без `#` (легаси).

## Когда прототип / `#`

- Списки, таблицы, тысячи entity.
- Методы читают `this` / `#field`.
- Хотите одну форму объектов для V8.

Проверяйте heap snapshot и CPU profile, а не «один `console.time` в DevTools».
