# 1. Тема

**Стандартные алгоритмы сортировки:** Bubble · Selection · Insertion · Quick · Merge · Timsort

---

# 2. Главное в одну фразу

Сортировка упорядочивает элементы по критерию; учебные O(n²) алгоритмы объясняют идею, а на практике в JS/TS почти всегда берут встроенный `.sort()` (Timsort) или гарантированный O(n log n) вроде Merge Sort.

---

# 3. Суть

> Алгоритмы сортировки расставляют элементы массива в нужном порядке. От выбора зависят время, память и **стабильность** — сохраняется ли относительный порядок равных ключей.
>
> Квадратичные Bubble / Selection / Insertion понятны и уместны на крошечных или почти отсортированных данных. Quick Sort и Merge Sort дают O(n log n) в типичном случае и лежат в основе «быстрых» сортировок; у Quick в худшем случае бывает O(n²), у Merge — стабильные O(n log n) ценой памяти O(n).
>
> В продакшене TypeScript/JavaScript вручную пишут сортировки редко: `Array.prototype.sort` в V8 использует **Timsort** (слияние + вставки). Классику всё равно полезно понимать: отладка, выбор структуры данных и задачи, где стандартный `.sort` не подходит.

---

# 4. Самое главное запомнить

- **O(n²):** Bubble, Selection, Insertion — учёба / очень маленькие n; Insertion хорош на почти отсортированных данных.
- **O(n log n):** Quick (в среднем), Merge (гарантированно); Quick хуже на неудачном pivot → O(n²).
- **Стабильность** — равные ключи не меняют взаимный порядок (важно при многоключевой сортировке).
- Merge — стабильный, доп. память O(n); Quick — обычно нестабильный, память стека O(log n).
- В JS/TS: **`.sort(compareFn)`** → Timsort в V8; не изобретать велосипед без причины.
- Сравнивайте не «красивость кода», а **worst/average**, память и стабильность под задачу.

# 5. Описание

## Зачем вообще несколько алгоритмов

Все они делают одно: расставляют элементы по порядку (меньше → больше). Разница в **способе**: одни много раз сравнивают соседей, другие делят массив на части. Простые удобны, чтобы понять идею; быстрые — чтобы не ждать на больших данных.

Ниже — «что делает руками», потом короткий код.

---

## Простые (медленные на больших массивах) — O(n²)

На тысячах элементов уже тяжело. Зато шаги легко проговорить вслух.

### Bubble Sort — «пузырёк»

**Идея:** идём слева направо и смотрим **пару рядом**. Если левый больше правого — меняем местами. После одного такого прохода самый большой элемент оказывается в конце (как пузырёк всплыл). Дальше снова проходим по оставшейся части — и так, пока всё не встанет по порядку.

Пример на `[3, 1, 2]`:

```text
3 1 2  →  1 3 2  →  1 2 3
(3>1)     (3>2)     готово
```

Если за целый проход ничего не поменяли — массив уже отсортирован, можно остановиться раньше.

```typescript
function bubbleSort(arr: number[]): number[] {
  const a = arr.slice();
  const n = a.length;
  for (let i = 0; i < n - 1; i++) {
    for (let j = 0; j < n - i - 1; j++) {
      if (a[j] > a[j + 1]) {
        [a[j], a[j + 1]] = [a[j + 1], a[j]];
      }
    }
  }
  return a;
}
```

### Selection Sort — «выбор минимума»

**Идея:** делим массив на «уже готово слева» и «ещё нет справа». На каждом шаге в правой части ищем **самый маленький** элемент и ставим его на первое свободное место слева (меняем с тем, что там лежит). Потом сдвигаем границу вправо.

Как разложить карты: каждый раз берёшь из оставшихся самую маленькую и кладёшь в конец уже собранной стопки.

```text
[3, 1, 4, 2]
 ↑ ищем min среди всех → 1, ставим на место 0
[1 | 3, 4, 2]
      ↑ min в хвосте → 2
[1, 2 | 4, 3]
         ↑ min → 3
[1, 2, 3, 4]
```

```typescript
function selectionSort(arr: number[]): number[] {
  const a = arr.slice();
  const n = a.length;
  for (let i = 0; i < n - 1; i++) {
    let minIdx = i;
    for (let j = i + 1; j < n; j++) {
      if (a[j] < a[minIdx]) minIdx = j;
    }
    if (minIdx !== i) [a[i], a[minIdx]] = [a[minIdx], a[i]];
  }
  return a;
}
```

### Insertion Sort — «вставка как в карты»

**Идея:** слева уже лежит аккуратная стопка. Берём следующий элемент справа и **вставляем его в нужное место** в стопке: сдвигаем вправо всё, что больше него, и кладём на освободившееся место.

Если массив почти по порядку, сдвигать почти нечего — работает быстро (близко к одному проходу). Если всё наоборот — много сдвигов, снова медленно.

```text
[3 | 1, 4, 2]  берём 1 → вставляем перед 3
[1, 3 | 4, 2]  берём 4 → уже больше 3, оставляем
[1, 3, 4 | 2]  берём 2 → сдвигаем 4 и 3, вставляем
[1, 2, 3, 4]
```

```typescript
function insertionSort(arr: number[]): number[] {
  const a = arr.slice();
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i - 1;
    while (j >= 0 && a[j] > key) {
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = key;
  }
  return a;
}
```

## Быстрые на больших данных — O(n log n)

Дробим задачу на части, сортируем части, собираем обратно.

### Quick Sort — «опорный элемент»

**Идея:**

1. Выбираем один элемент — **опору** (pivot), например из середины.
2. Раскладываем остальные: всё, что меньше опоры — налево, что больше — направо (равные можно в середину).
3. То же самое **рекурсивно** делаем с левой кучей и с правой.
4. Склеиваем: отсортированное левое + опора + отсортированное правое.

Похоже на сортировку вещей вокруг выбранной «точки отсчёта»: сначала разложили по сторонам, потом навели порядок в каждой куче.

В среднем получается быстро. Если опора постоянно неудачная (например, почти всегда самый маленький элемент), кучи получаются кривыми и алгоритм может стать таким же медленным, как простые.

Ниже — учебный вариант через `filter` (понятно читать; в «боевых» реализациях обычно переставляют элементы на месте).

```typescript
function quickSort(arr: number[]): number[] {
  if (arr.length <= 1) return arr;

  const pivot = arr[Math.floor(arr.length / 2)]!;
  const left = arr.filter((x) => x < pivot);
  const middle = arr.filter((x) => x === pivot);
  const right = arr.filter((x) => x > pivot);

  return [...quickSort(left), ...middle, ...quickSort(right)];
}
```

### Merge Sort — «раздели и слей»

**Идея:**

1. Режем массив пополам, половины — ещё пополам, пока не останутся кусочки из одного элемента (один элемент уже «отсортирован»).
2. Потом **сливаем** пары кусочков в один упорядоченный: смотрим на начала двух куч и каждый раз забираем меньший элемент.
3. Так собираем всё обратно вверх по дереву разрезов.

```text
[3, 1, 4, 2]
   /      \
[3, 1]   [4, 2]
 /  \     /  \
[3] [1] [4] [2]
 \  /     \  /
[1, 3]   [2, 4]
   \      /
  [1, 2, 3, 4]
```

Время всегда предсказуемое: O(n log n). Минус — нужна дополнительная память под результат слияния. Плюс — **стабильный**: равные элементы не меняются местами без нужды.

```typescript
function mergeSort(arr: number[]): number[] {
  if (arr.length <= 1) return arr;

  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));
  return merge(left, right);
}

function merge(left: number[], right: number[]): number[] {
  const result: number[] = [];
  let i = 0;
  let j = 0;
  while (i < left.length && j < right.length) {
    if (left[i]! <= right[j]!) result.push(left[i++]!);
    else result.push(right[j++]!);
  }
  return result.concat(left.slice(i), right.slice(j));
}
```

## Сравнение одной таблицей

| Алгоритм | Лучшее | Среднее | Худшее | Память | Стабильность |
|----------|--------|---------|--------|--------|--------------|
| Bubble | O(n)* | O(n²) | O(n²) | O(1) | Да |
| Selection | O(n²) | O(n²) | O(n²) | O(1) | Нет |
| Insertion | O(n) | O(n²) | O(n²) | O(1) | Да |
| Quick | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет** |
| Merge | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |

\* если заметили, что за проход не было обменов.  
\*\* обычный Quick «на месте» порядок равных элементов не обещает.

**Стабильность простыми словами:** если два человека одного возраста, после сортировки по возрасту они остаются в том же порядке друг относительно друга, что был до сортировки — у стабильного алгоритма. Это важно, когда сортируете сначала по одному полю, потом по другому.

## Практика в JavaScript / TypeScript

В Chrome / Node (движок V8) встроенный `Array.prototype.sort` — это **Timsort**: смесь вставок и слияния. Он хорошо ловит куски, которые уже почти по порядку. В обычном коде пишите `.sort`, а не свой Quick.

```typescript
interface User {
  name: string;
  age: number;
}

const users: User[] = [
  { name: 'Bob', age: 30 },
  { name: 'Alice', age: 25 },
  { name: 'Charlie', age: 30 },
];

users.sort((a, b) => {
  if (a.age !== b.age) return a.age - b.age;
  return a.name.localeCompare(b.name);
});
// Alice(25), Bob(30), Charlie(30)
```

Без функции сравнения числа сортируются как строки: `10` окажется перед `2`. Для чисел всегда передавайте `(a, b) => a - b`.

## Когда что выбирать

1. **Понять идею / крошечный массив** — Insertion или Selection.
2. **Нужна гарантия времени и стабильность** — Merge (или просто довериться Timsort).
3. **Обычный продукт** — `.sort(compareFn)`.

## Частые развилки

- **Quick vs Merge** — Quick часто быстрее и меньше ест память, но в худшем случае может «просесть»; Merge ровнее по времени, но просит доп. память.
- **Стабильность** — нужна, когда важен прежний порядок равных ключей.
- **В V8** — `.sort` ≈ Timsort.
- **Свой Quick в проде** — легко ошибиться на краях и опоре; библиотека уже проверена.
