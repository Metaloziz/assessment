# 1. Тема

**Что такое алгоритмы**

---

# 2. Главное в одну фразу

Алгоритм — конечная последовательность понятных шагов, которая из входных данных получает нужный результат; структура данных — способ хранить эти данные так, чтобы шаги были дешёвыми.

---

# 3. Суть

> Алгоритм — это рецепт решения задачи: чёткие шаги, конечное число действий, однозначный результат для допустимого входа. В коде это функция или процедура; в жизни — сортировка почты, поиск в словаре, маршрутизация заказа.
>
> Его оценивают не только «работает / не работает», а сколько шагов и памяти нужно при росте входа. Отсюда Big O и выбор структур данных: массив удобен для доступа по индексу, хеш-таблица — для поиска по ключу, дерево — для упорядоченных диапазонов.
>
> Алгоритм не равен «хитрому трюку на собеседовании». Любой понятный процесс с конечным числом шагов — уже алгоритм; вопрос в том, насколько он устойчив и дёшев на реальных объёмах данных.

---

# 4. Самое главное запомнить

- **Алгоритм** = конечные, однозначные шаги: вход → выход.
- **Корректность** — даёт верный ответ; **эффективность** — сколько стоит по времени и памяти.
- **Структура данных** задаёт, какие операции дёшевы (доступ, вставка, поиск).
- Один и тот же результат можно получить разными алгоритмами с разной сложностью.
- Сначала ясная постановка задачи и ограничения, потом код и оптимизация.
- «Работает на 10 элементах» ≠ «выдержит миллион».

# 5. Описание

## Из чего состоит постановка

```text
задача → вход / выход → ограничения (n, память, realtime)
       → алгоритм → структура данных → оценка (время, память)
       → проверка на краях и больших n
```

Пример: «найти пользователя по id».

| Подход | Идея | Цена при большом n |
|--------|------|--------------------|
| Линейный проход по массиву | Смотрим каждый элемент | Растёт вместе с n |
| Словарь / `Map` по id | Один lookup по ключу | Почти константа в среднем |
| Отсортированный список + бинпоиск | Делим диапазон пополам | Логарифм от n |

Один ответ — разные алгоритмы и структуры.

## Свойства «хорошего» алгоритма на практике

1. **Конечность** — завершается (или явно ограничен таймаутом / отменой).
2. **Определённость** — шаги не двусмысленны.
3. **Корректность** — на допустимых входах даёт нужный результат; на недопустимых — контролируемую ошибку.
4. **Понятность** — коллега может прочитать и изменить через полгода.
5. **Масштабируемость** — поведение при росте данных предсказуемо.

## Алгоритм и структура данных

Структура данных — «полка», на которой лежат значения. Алгоритм — «как по полке ходить».

- Плохой алгоритм на хорошей структуре всё равно будет медленным (например, полный перебор вместо индекса).
- Сильный алгоритм на неподходящей структуре упрётся в дорогие операции (частые вставки в середину массива).

На фронтенде это те же идеи: фильтрация списка, дедупликация, поиск в автокомплите, виртуализация — везде есть вход, шаги и цена.

## Типичные вопросы на собеседовании

- Что такое алгоритм? — Конечная последовательность шагов от входа к выходу.
- Чем отличается от программы? — Программа — реализация (часто нескольких алгоритмов) на языке и платформе.
- Зачем структуры данных? — Чтобы нужные операции были дешёвыми.
- С чего начинать задачу? — Уточнить вход/выход, ограничения и что считать «достаточно быстро».
