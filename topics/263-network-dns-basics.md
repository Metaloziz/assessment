# 1. Тема

**Базовое понимание DNS**

---

# 2. Главное в одну фразу

DNS переводит человекочитаемое имя в IP-адрес, без которого сеть не знает, куда слать пакеты.

---

# 3. Суть

> **DNS** — телефонная книга интернета. Вы пишете `api.example.com`, а компьютеру нужен **IP** вроде `203.0.113.10`. DNS как раз отвечает: «у этого имени такой адрес».
>
> Без этого шага сайт по имени не откроется: некуда соединяться. Ошибка часто выглядит как `ENOTFOUND` — ещё до HTTP и «сайт лежит». Имя удобно людям и конфигам; пакеты всегда идут по IP.
>
> Как это происходит. Браузер или Node видит hostname → спрашивает DNS → получает IP → только потом открывает соединение. Ответ DNS на время запоминают, поэтому после смены адреса у сервера кто-то ещё какое-то время ходит на старый IP.
>
> Ловушка: путать «DNS не нашёл имя» с «сервер не отвечает». Это разные поломки. Имя и адрес — разные вещи (тема «IP-адрес и hostName»); DNS их только связывает.

---

# 4. Самое главное запомнить

- DNS отвечает на вопрос «какой IP у этого имени?», не открывает страницу сам.
- Пока имя не превратилось в адрес, TCP и HTTP ещё не начались.
- `ENOTFOUND` / «не удаётся найти сервер» — обычно DNS; «соединение отклонено» — уже хост и порт.
- Ответ помнят некоторое время: смена IP видна не сразу у всех.
- Файл hosts на компьютере может подменить имя раньше DNS — удобно для отладки, легко забыть.
- Кроме адреса у имени бывают и другие данные (почта, текст), но для `fetch` нужен именно IP.

# 5. Описание

```text
в коде / URL:   api.example.com
                     │
                     ▼
                   DNS  →  203.0.113.10
                     │
                     ▼
              соединение по IP
```

## Зачем это нужно

Люди и конфиги держат имена: `https://api.example.com`, `HOST=db.internal`. Сеть доставляет пакеты по числу — IP. DNS — сервис, который держит эту связку. Сервер можно переехать на другой адрес, а клиенты по-прежнему пишут то же имя — если обновить запись в DNS.

## Как спрашивают

1. Клиент берёт hostname из URL или конфига.
2. Спрашивает DNS (или сначала локальный файл hosts).
3. Получает IP и соединяется уже с ним.

В Node это часто незаметно: `fetch('https://api.example.com/...')` сам резолвит имя. Явно то же самое:

```js
import dns from 'node:dns/promises';

const { address } = await dns.lookup('api.example.com');
// дальше соединение идёт на address
```

Запись **A** — IPv4, **AAAA** — IPv6. Для открытия сайта нужен хотя бы один адрес. Остальные типы (почта, произвольный текст) к `fetch` обычно не относятся.

## Если имени нет

DNS может ответить «такого имени нет». Тогда адреса нет, соединение не начнётся. Это не то же самое, что сервер выключен: хост может быть жив, просто вы опечатались в имени — или наоборот, имя резолвится, а порт закрыт.

Локальный **hosts** (`/etc/hosts` или `C:\Windows\System32\drivers\etc\hosts`) может жёстко сказать: это имя = вот этот IP, без опроса DNS. После эксперимента строку легко забыть и долго искать «почему у меня другой адрес».

## DNS помнит ответ

Ответ не спрашивают каждый раз заново: его держат какое-то время (**TTL**). Отсюда «я уже сменил IP у сервиса, а коллега всё ещё попадает на старый». Это ожидаемо, не баг приложения.

## Ловушки

- Ждать, что смена адреса в панели DNS мгновенно видна всем.
- Считать любую ошибку «не открывается» ошибкой DNS — сначала проверьте, нашлось ли имя.
- Захардкодить IP вместо имени: переезд сервера сломает клиентов.
- Оставить тестовую строку в hosts.

Имя vs адрес — тема «IP-адрес и hostName». Как пакет идёт по IP — «Базовое понимание IP». Здесь важен один шаг: **сначала имя становится адресом**.
