# 1. Тема

**Grid:** треки · области · `fr` / `minmax` · авто-поток

---

# 2. Главное в одну фразу

CSS Grid раскладывает элементы в двумерной сетке строк и колонок — каркас страницы и плитки задают треки и области, а не цепочки вложенного flex.

---

# 3. Суть

> **CSS Grid** — модель раскладки для **двух осей сразу**: контейнер с `display: grid` делит пространство на **треки** (колонки и строки), а дочерние элементы занимают **ячейки** или именованные **области**. В отличие от Flexbox (одна главная ось, вторая — выравнивание), Grid изначально проряжает плоскость: шапка на всю ширину, сайдбар слева, контент справа — без обёртки «колонка в колонке».

> Зачем: каркас приложения, дашборд, галерея карточек с выравниванием по рядам. Один контейнер описывает структуру; меняется ширина окна — треки с `fr` и `minmax` перераспределяют свободное место, а не ломают DOM ради новой вложенности.

> Как устроено. Задают `grid-template-columns` / `grid-template-rows` (или `grid-template-areas` — карта имён). Элементы кладут через `grid-area`, `grid-column` / `grid-row` или оставляют **авто-потоку**: браузер заполняет ячейки по порядку DOM. `gap` — зазор между треками; `fr` — доля свободного пространства; `minmax(min, max)` — трек не схлопнется ниже минимума и не раздуется бесконтрольно.

> Ловушка: смешивать «сетку» с flex-обёртками на каждый ряд и думать, что это то же самое. Или задать только колонки и ждать «макет страницы» — без строк/областей элементы поедут авто-потоком не туда. Ещё: `1fr` ≠ `%` внутри вложенного грида с `minmax(0, 1fr)` — без нулевого минимума контент часто раздувает трек.

---

# 4. Самое главное запомнить

- Grid — **2D** (строки + колонки); Flex — **1D** (ряд или столбец).
- Треки задают `grid-template-columns` / `rows`; каркас страницы удобно класть в `grid-template-areas`.
- `fr` делит **свободное** место после фиксированных треков и `gap`.
- Без явного размещения работает авто-поток: порядок = порядок в DOM (плюс `grid-auto-flow`).
- `minmax(0, 1fr)` часто нужен, чтобы длинный контент не раздувал колонку.
- Flex и Grid дополняют друг друга: Grid — каркас, Flex — ряд кнопок / выравнивание внутри ячейки.

# 5. Описание

```text
  display: grid
       │
       ├─ template columns / rows   ← треки (px, %, fr, minmax, auto)
       ├─ template areas            ← карта имён: "header header" …
       ├─ gap                       ← между треками
       │
       └─ дети
            ├─ grid-area / column / row   ← явное место
            └─ иначе авто-поток           ← по DOM в свободные ячейки
```

## Контейнер и треки

```css
.layout {
  display: grid;
  grid-template-columns: 12rem 1fr;
  grid-template-rows: auto 1fr auto;
  gap: 0.75rem;
  min-height: 100vh;
}
```

Колонки: узкий сайдбар + растягивающийся контент. Строки: шапка по контенту, середина забирает оставшуюся высоту, подвал снизу. `1fr` — не «процент родителя», а доля **остатка** после `auto`/`px` и `gap`.

## Области (`grid-template-areas`)

Имена рисуют макет текстом — удобно читать и менять брейкпоинты одной картой:

```css
.layout {
  display: grid;
  grid-template-columns: 12rem 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "nav    main"
    "footer footer";
}

.header { grid-area: header; }
.nav    { grid-area: nav; }
.main   { grid-area: main; }
.footer { grid-area: footer; }
```

На узком экране ту же семантику DOM оставляют, а области переписывают в одну колонку (`"header" "nav" "main" "footer"`).

## Явное размещение и span

Без areas можно указать линии:

```css
.hero {
  grid-column: 1 / -1; /* от первой линии до последней */
  grid-row: 1 / 2;
}
```

`span 2` занимает две клетки. Линии нумеруются с 1; отрицательные считают с конца (`-1` — последняя линия).

## Авто-поток

Если у ребёнка нет `grid-area` / линий, браузер кладёт его в следующую свободную ячейку. `grid-auto-flow: row` (по умолчанию) заполняет ряды; `column` — колонки; `dense` пытается закрыть дыры (может переставить визуальный порядок относительно DOM — осторожно с доступностью).

Неявные треки создаёт `grid-auto-rows` / `grid-auto-columns`, когда элементов больше, чем ячеек в шаблоне.

## `fr`, `minmax`, выравнивание

| Запись | Смысл |
| --- | --- |
| `1fr 2fr` | свободное место 1:2 |
| `minmax(12rem, 20rem)` | трек в коридоре min…max |
| `minmax(0, 1fr)` | доля fr, но контент не раздувает трек выше родителя |
| `repeat(3, 1fr)` | три равные колонки |
| `repeat(auto-fill, minmax(12rem, 1fr))` | столько колонок, сколько влезает |

Выравнивание: `justify-items` / `align-items` — ячейки; `justify-content` / `align-content` — вся сетка в контейнере, если треки меньше родителя. Для одного элемента — `justify-self` / `align-self`.

## Grid и Flex

```text
  Grid:  каркас страницы / 2D плитка
  Flex:  тулбар, чипы, вертикальный стек в ячейке
```

Типичный стек: снаружи Grid-области, внутри `main` — Flex для шапки секции и списка. Пытаться собрать тот же каркас только Flex’ом — лишние обёртки и хрупкие «равные высоты» через трюки.

## Частые ловушки

- Забыли `minmax(0, …)` — таблица или длинное слово раздувает колонку, появляется горизонтальный скролл.
- `gap` + проценты без учёта: проценты считаются от размера контейнера, `fr` — от свободного места после gap.
- Путают `grid` и `inline-grid`: второй ведёт себя как инлайн-бокс по внешнему потоку.
- Перекрытие ячеек без плана: два элемента на одну область — рисуются стопкой (нужен осознанный stacking, не «случайный баг»).
