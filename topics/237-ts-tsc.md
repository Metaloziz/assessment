# 1. Тема

**Использование tsc**

---

# 2. Главное в одну фразу

`tsc` — командная утилита TypeScript: читает настройки проекта, проверяет типы и по желанию записывает обычный JavaScript (и `.d.ts`) на диск.

---

# 3. Суть

> `tsc` — **официальная утилита командной строки** компилятора TypeScript. Вы запускаете её по проекту или списку файлов: она собирает программу из `.ts` / `.tsx`, сверяет типы в вызовах и присваиваниях, а затем либо **пишет** `.js` (и при необходимости `.d.ts`) в папку сборки, либо **только сообщает** об ошибках и завершается с кодом ≠ 0.
>
> Зачем. В библиотеках и простых Node-сервисах `tsc` часто **и проверяет, и собирает** артефакты в `dist`. В приложении на Vite или webpack транспиляцию делает **быстрый** бандлер, а `tsc --noEmit` гоняют отдельно — в CI или перед коммитом. Смысл проверки тот же, но emit не дублируют.
>
> Как запускать: `tsc -p tsconfig.json` (явный проект), `tsc --noEmit` (только проверка), `tsc -w` (перепроверка при сохранении). Флаги CLI **перекрывают** поля `compilerOptions`; без `-p` утилита ищет ближайший `tsconfig.json` вверх по каталогам.
>
> Ловушка: путать «собралось в Vite» и «типы прошли». Бандлер может выдать JS при ошибках типов, если checker не в пайплайне. И наоборот: зелёный `tsc` не валидирует JSON с сервера — типы стираются, внешние данные всё равно проверяют явно.

---

# 4. Самое главное запомнить

- `tsc` проверяет типы и при необходимости пишет JS и `.d.ts`.
- Настройки — в `tsconfig.json`; `-p` указывает файл проекта; флаги CLI важнее полей конфига.
- `--noEmit` — только проверка без файлов на диске (часто CI + Vite/esbuild).
- Emit: `outDir`, `target`, `module`, `declaration` — куда и во что писать.
- `-w` перепроверяет при сохранении; `incremental` ускоряет повторные прогоны.
- Успешная сборка бандлером без `tsc` не гарантирует зелёные типы; зелёный `tsc` не делает рантайм безопасным.

---

# 5. Описание

```text
.ts / .tsx  +  tsconfig.json
        │
        ▼
   ┌─────────┐
   │   tsc   │  читает проект → проверяет типы
   └────┬────┘
        │
   ┌────┴────┐
   │         │
   ▼         ▼
 пишет JS   --noEmit
 (+ .d.ts)  (только код выхода и сообщения)
```

## Запуск и проект

Без аргументов `tsc` ищет `tsconfig.json` вверх по каталогам. Явно указать проект:

```bash
tsc -p tsconfig.json
tsc -p tsconfig.build.json --noEmit
```

В `package.json` обычно два скрипта: сборка с записью файлов и отдельная проверка типов.

```json
{
  "scripts": {
    "build": "tsc -p tsconfig.build.json",
    "typecheck": "tsc -p tsconfig.json --noEmit"
  }
}
```

## Запись файлов vs только проверка

| Режим | Что делает | Когда |
|---|---|---|
| `tsc` (emit) | пишет `.js` (и `.d.ts` при `declaration`) | библиотека, Node без бандлера |
| `tsc --noEmit` | только диагностика, exit ≠ 0 при ошибках | CI, проекты на Vite/webpack |
| `tsc -w` | watch: повторный check/emit при изменениях | локальная разработка |

`noEmitOnError: true` (в конфиге) не пишет выход, если проверка упала — полезно, чтобы в `dist` не лежали «битые» артефакты.

## Ключевые опции

Короткий фрагмент `tsconfig`:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "NodeNext",
    "outDir": "dist",
    "rootDir": "src",
    "strict": true,
    "declaration": true,
    "noEmit": false
  },
  "include": ["src"]
}
```

- `target` / `module` — синтаксис и система модулей на выходе.
- `outDir` / `rootDir` — зеркало дерева исходников в `dist`.
- `strict` — пакет строгих проверок (база для надёжного check).
- `declaration` — рядом с JS писать `.d.ts` для потребителей библиотеки (см. тему про файлы декларации).
- `skipLibCheck` — не перепроверять все `.d.ts` в `node_modules` (быстрее CI; не отменяет check своего кода).

## Связка с бандлером

Vite и esbuild быстро превращают `.ts` в JS и **не** делают полную проверку типов. Паттерн: dev/build через бандлер, типы — отдельным `tsc --noEmit` (или плагином в IDE). Так обратная связь остаётся быстрой, а контракты не «проскакивают» в merge.

## Диагностика

Ошибки печатаются с путём, строкой и кодом (`TS2322` и т.д.). Exit code ≠ 0 — сигнал для CI. `pretty: true` (по умолчанию в современных версиях) подсвечивает контекст; для машинного разбора удобен `--pretty false` или JSON-репортёры в обвязке.
