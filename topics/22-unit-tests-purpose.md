# 1. Тема

**Назначение unit-тестов**

---

# 2. Главное в одну фразу

Unit-тесты проверяют маленькие изолированные части кода, чтобы быстро ловить регрессии и фиксировать ожидаемое поведение на уровне модулей.

---

# 3. Ответ для собеседования

> «Unit проверяет функцию/класс/компонент **изолированно**, без реальной БД/сети/UI.
>
> Назначение: контракт входов/выходов, быстрые регрессии, документация поведения, безопасный рефакторинг, дешёвая локализация бага.
>
> Свойства: быстрые, стабильные, локальные; зависимости мокают.
> Не заменяют integration/e2e. Тестируем поведение, а не каждую private-деталь. Фундамент пирамиды тестирования.»

---

# 4. Самое главное запомнить

- Изолированная проверка одной единицы.
- Регрессии + документация + быстрый feedback.
- Моки внешних зависимостей.
- Не замена e2e.
- Поведение > внутренности.

---

# 5. Описание

| Тип | Что | Скорость |
|-----|-----|----------|
| Unit | Модуль в изоляции | Очень быстро |
| Integration | Связка модулей | Средне |
| E2E | Сценарий пользователя | Медленно |

Пирамида: много unit → меньше integration → ещё меньше e2e.
