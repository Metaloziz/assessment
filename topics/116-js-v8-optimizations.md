# 1. Тема

**Оптимизации V8**

---

# 2. Главное в одну фразу

V8 ускоряет доступ к свойствам и вызовы, когда видит стабильные формы объектов и предсказуемые типы на горячем пути.

---

# 3. Суть

> Для объектов схожей структуры V8 создаёт внутренние shapes (часто называемые hidden classes) и использует inline caches, чтобы не искать свойство заново при каждом доступе. JIT специализирует код по наблюдённым типам и может инлайнить вызовы; частая смена форм, типов или переопределение встроенных свойств делает путь полиморфным либо мегаморфным и способно привести к deopt.

---

# 4. Самое главное запомнить

- Hidden class описывает форму и порядок добавленных свойств, это внутренняя деталь V8.
- Monomorphic inline cache — один ожидаемый shape; polymorphic — несколько; megamorphic — много.
- Инициализация полей в одном порядке в конструкторе помогает сохранять общую форму.
- `delete`, добавление разных полей и смешивание типов в hot path могут ухудшить оптимизацию.
- Это эвристики V8: сначала профиль, затем изменение кода, если измерения показывают проблему.

---

# 5. Описание

```js
class Point {
  constructor(x, y) {
    this.x = x; // одинаковый порядок у всех экземпляров
    this.y = y;
  }
}

function lengthSquared(point) {
  return point.x * point.x + point.y * point.y;
}
```

Плохой для предсказуемости сценарий:

```js
const point = { x: 1 };
if (Math.random() > 0.5) point.y = 2;
else point.label = 'A'; // разные формы объектов
```

Не стоит утверждать, что скрытые классы превращают JavaScript в статически типизированный язык или что есть фиксированный порог deopt. Реальный эффект зависит от версии движка, платформы и профиля. Для расследования используют Chrome DevTools Performance и профили Node.js; V8-специфичные diagnostic flags не включают в production.
