# 1. Тема

**Оптимизации V8:** hidden classes / shapes · inline caches · monomorphic / mega · elements kinds · измерять, не гадать

---

# 2. Главное в одну фразу

V8 ускоряет доступ к свойствам и вызовы, когда на горячем пути стабильны формы объектов и предсказуемы типы — через hidden classes и inline caches.

---

# 3. Суть

> V8 не «магически ускоряет любой JS». Он запоминает, в каком порядке у объектов появляются поля (внутренняя **форма** / hidden class), и на месте вызова кэширует, откуда брать свойство (**inline cache**).
>
> В горячем цикле одинаково собранные модели (одни и те же поля в одном порядке) проходят быстрее, чем зоопарк объектов с разными наборами ключей. Это деталь движка, а не закон дизайна каждого DTO в системе.
>
> Ломают предсказуемость: разный порядок полей, `delete`, смешение типов на одном call site, «то число, то строка». Тогда кэш становится полиморфным / мегаморфным, код — общим, возможен deopt. Правило: сначала профиль, потом правка.

---

# 4. Самое главное запомнить

- Hidden class (shape) — внутренняя форма объекта: какие поля и в каком порядке.
- Inline cache (IC): monomorphic (одна форма) → polymorphic (несколько) → megamorphic (много, медленнее).
- Инициализируйте поля в конструкторе в одном порядке.
- `delete`, редкие поля «на лету», смешанные типы в hot path — риск.
- Elements kinds (плотные массивы чисел vs holey / объекты) тоже влияют на скорость массивов.
- Нет фиксированного порога deopt «на все версии V8» — смотрите Performance / профилировщик.

# 5. Описание

## Стабильная форма

```js
class Point {
  constructor(x, y) {
    this.x = x; // один порядок у всех экземпляров
    this.y = y;
  }
}

function lengthSquared(point) {
  return point.x * point.x + point.y * point.y; // один call site → один ожидаемый shape
}
```

```text
{ x, y } ──одна shape──► IC lengthSquared: monomorphic
{ x } потом y или label ──разные shapes──► polymorphic / megamorphic
```

## Плохо для предсказуемости

```js
const point = { x: 1 };
if (Math.random() > 0.5) point.y = 2;
else point.label = 'A'; // разные формы
```

## Inline caches (идея)

На участке `obj.x` движок кэширует: «для этой формы поле `x` лежит тут». Если приходят объекты одной формы — hit. Если формы пляшут — кэш раздувается и дорожает.

## Elements kinds (массивы)

Плотный `number[]` без дыр оптимизируется иначе, чем массив со `undefined`-дырами или смешанным содержимым. `arr[1] = undefined` / `delete arr[i]` могут сменить вид элементов.

## Практика

1. Пишите ясный код.
2. Измерьте hot path (Performance, CPU profile).
3. Если видно давление / deopt — упростите формы и типы там.
4. Не переписывайте весь проект «под hidden classes» заранее.
