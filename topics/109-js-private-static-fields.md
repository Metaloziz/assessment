# 1. Тема

**Приватные и статические поля классов**

---

# 2. Главное в одну фразу

Приватные поля `#name` принадлежат конкретному классу и недоступны извне, а `static`-члены принадлежат конструктору, а не экземпляру.

---

# 3. Суть

> Приватное поле с `#` доступно только коду внутри объявившего его класса. Это проверяемое языком правило, а не соглашение вроде `_name`: получить поле через квадратные скобки или перечисление свойств нельзя.
>
> Оно нужно, когда объект должен сам хранить инварианты: состояние подключения, баланс или внутренний кэш. `static` используют для данных и методов, общих для всего класса, например фабрики или счётчика экземпляров.
>
> Экземпляр обращается к своему полю как `this.#value`, а класс — к общему члену как `Class.value` или `Class.#value`. Приватное имя родителя недоступно даже подклассу с таким же написанием. Общее изменяемое `static`-состояние легко становится скрытым глобальным кэшем, поэтому ему нужны правила очистки и доступа.

---

# 4. Самое главное запомнить

- `this.#value` доступно только в теле класса, где поле объявлено.
- Приватные поля не являются свойствами объекта: их не видно в `Object.keys`, нельзя обратиться через `obj['#value']`.
- Подкласс не получает доступ к private names родителя; одинаковое имя `#x` в двух классах — разные поля.
- Статические методы и поля вызываются через класс: `User.create()`, а не через экземпляр.
- В статическом методе `this` — класс-получатель, что важно при наследовании.

---

# 5. Описание

```js
class ConnectionPool {
  static #opened = 0;
  #closed = false;

  constructor() {
    ConnectionPool.#opened++;
  }

  close() {
    this.#closed = true;
  }

  static get opened() {
    return this.#opened;
  }
}

const pool = new ConnectionPool();
pool.close();
ConnectionPool.opened; // 1
```

Private fields полезнее замыканий, когда методы можно хранить на прототипе и не создавать по функции на каждый экземпляр. В отличие от TypeScript-модификатора `private`, JavaScript `#private` действует и во время выполнения: попытка синтаксически обратиться к нему снаружи — ошибка.

Статические поля наследуются по цепочке конструкторов, но приватное статическое поле имеет brand конкретного класса. Не используйте общее изменяемое `static`-состояние как скрытый глобальный кэш без правил очистки.
