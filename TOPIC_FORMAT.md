# Правила оформления тем (`topics/*.md`)

Документ фиксирует формат заметок для assessment. Старые темы **не переписываем** массово — правила применяются к новым и к тем, которые правим по одной.

## Структура файла

1. **Тема** — заголовок без маркеров уровня `(🟩)/(🟧)/(🟪)`.
2. **Главное в одну фразу** — одна плотная фраза.
3. **Суть** — выдержка по теме (см. ниже). Раньше раздел назывался «Ответ для собеседования»; в новых файлах только **Суть**.
4. **Самое главное запомнить** — буллеты / короткая таблица.
5. **Описание** — детали, примеры, сравнения.
6. **Ссылки** — первоисточники.

## Раздел «Суть»

- В markdown: `# 3. Суть` (не «Ответ для собеседования»).
- В UI показывается как **Суть**.
- Это **выдержка с сутью темы**, а не монолог от первого лица («я бы ответил…», «на собеседовании скажу…»).
- Допустимы цитаты-блоки `>` для плотного абзаца, но без театрального «как будто отвечает кандидат».
- Фокус: определение, зачем нужно, границы применения, типичные ловушки.

### Плохо

> «Я обычно запускаю ts-prune и смотрю, что у меня не используется…»

### Хорошо

> **ts-prune** находит неиспользуемые TypeScript-экспорты. **Statoscope** анализирует webpack-бандл: дубликаты, unused modules, размер чанков. Вместе помогают отличать «мертвый» код в исходниках от «мертвого» в сборке.

## Общие правила

- Язык: русский.
- Код — короткие иллюстрации, без лишнего шума.
- Уровень темы задаётся в `app/src/content/groups.ts` по цвету Notion (🟩 junior / 🟧 middle / 🟪 senior), не пишется в заголовок markdown.
- Лаборатории и квизы — только если явно попросили; по умолчанию теория.
