# Как писать лабы assessment

Проектный скилл (`skills/` в корне репо). Полные правила — [`LAB_FORMAT.md`](../../LAB_FORMAT.md).

Связанный скилл теории: [`write-assessment-topics`](../write-assessment-topics/SKILL.md).

### Скилл визуализаций — обязательно, если есть картина

Если на «Решении проблемы» есть **что визуализировать** (схема, узлы, поток, before/after, анимация состояний) — **сначала прочитай целиком** [`assessment-lab-visualizations/SKILL.md`](../assessment-lab-visualizations/SKILL.md) и следуй ему. Недостаточно «вспомнить» `LabVizPanel` или скопировать соседнюю лабу: токены, панель, анимация, SVG-типографика — из того скилла.

Если картины **не будет** (см. § «Без визуализации») — скилл визуализаций **не** читать и **не** тащить `LabVizPanel` / GSAP «для галочки».

## Когда лаба нужна

| Уровень (`groups.ts`) | Лаба |
|------------------------|------|
| **middle** / **senior** | **обязательна** |
| **junior** | только по явной просьбе |

## Стенд, не статья

На экране — **одна** картина выбранного механизма. За 10–20 секунд ясно: что сломано, что выбрать, что нажать, что изменилось.

Вкладки UI **две** (не три): **Код** и **Решение проблемы**. Схема живёт на «Решении проблемы», не отдельной вкладкой.

### Дизайн до кода

0. Сначала честно: **есть ли что показать глазу?** (состояние, поток, DOM/API-эффект, look). Если нет — см. § «Без визуализации», шаги 2–4 про картину **пропустить**.
1. **Сверка с живым API / инфрой** (до выбора `LabNode`):
   - Открыть [`docs/FRANKENSTEIN_PLAN.md`](../../docs/FRANKENSTEIN_PLAN.md) — строка темы: **API** / **оба** / не в бэклоге.
   - Глянуть `server/` (роуты, `db.ts`, `DATABASE_URL`), smoke (`/api/demo/db-ping`, CorsLab и т.п.) и `hasApi` в `parseTopicMd.ts`.
   - Если в плане **API** или **оба**, либо уже есть подходящий бэк/БД — **живой вариант считается возможным**; молча не уходить в одни узлы.
   - **Ограничение:** live по HTTP допустим только по § «Где может жить live» ниже — не планировать стенд с локальным `server` у пользователя.
2. Есть схема / визуализация → **прочитать** [`assessment-lab-visualizations`](../assessment-lab-visualizations/SKILL.md) (обязательно).
3. Выбрать механизм **или** кластер с переключателем (на экране всё равно одна картина).
4. Выбрать **вид картины** (не по привычке к `LabNode`):

   | Вид | Когда уместен | Эталон |
   |-----|----------------|--------|
   | **Живой механизм** | Эффект можно **увидеть/потрогать** в браузере тем же API, что в теме (`createPortal`, Error Boundary, `overflow`+clip, focus, реальный HTTP-стенд…) | `react-portals`, `react-error-boundaries`, CorsLab |
   | **Живой UI-образец** | Тема про **look** (токены, типографика, contrast) | `layout-design-system` |
   | **Механизм узлами** | Абстрактная структура/шаги: граф, стек, кэш, паттерн-связи, пайплайн без «живого» DOM-эффекта | `algorithms-stack-hashmap`, mediator |
   | **Без картины** | Нечего анимировать и нечего честно нарисовать узлами — чистый синтаксис / декларации / конфиг; смысл в файлах на «Код» | `ts-declaration-files` |

   **Правило выбора:** если абстрактные узлы **прячут** эффект (обрезание, портал в другом DOM, fallback UI, ошибка сети, реальный ответ БД/HTTP) — кандидат на **живой механизм**, не схему `#root → Card → Modal`. Если «пощупать» нельзя без фейка целого движка — узлы/метафора. Не копировать горизонтальный `A → B → C`, если тема не про пайплайн запроса. Не клеить статичные `LabNode` «app → .d.ts → .js», если это только пересказ теории без нового состояния. Если есть **разветвление событий** (hit/miss, early return vs continue) — **развилка**, не вертикальный стек блоков; эталон `nodejs-cache-crud` (см. [`assessment-lab-visualizations`](../assessment-lab-visualizations/SKILL.md) § «Развилка событий»).

   **Вопрос пользователю, если живой стенд возможен.** Перед кодом картиной/роутами **остановись и задай вопрос** с кратким описанием варианта (что дернётся: роут, БД, DOM-API; что увидит глаз; что останется узлами/сниппетами, если live частичный). Дождись явного ок / «делаем живой» / выбора альтернативы. **Молча не пиши** ни live-роуты, ни «на всякий случай» только `LabNode`, когда live возможен.

   Самопроверка перед вопросом:

   - Эффект реально показать **тем же API** / через существующий `server`+БД, без фейка движка / вложенного рантайма?
   - Уложится в обычный объём лабы — или нужна новая тяжёлая инфра (вторая БД, отдельный сервис)?

   Если **не уверен** или видно, что **дорого** — в том же вопросе опиши риск и предложи запасной вариант (узлы / UI-образец / без картины / частичный live). Код живого механизма — **только после согласия**. Молча не уходи в долгую реализацию и не подменяй запланированный live одними узлами без вопроса.

### Где может жить live (обязательное ограничение)

Live-стенд с **HTTP/API** допустим только если лаба работает **без локального запуска `server`** у пользователя:

| Вариант | Когда |
|---------|--------|
| **Только фронт** | DOM / React / Web API — эффект виден в браузере без бэка (`createPortal`, Error Boundary, `overflow`…) |
| **Удалённый assessment-api** | Роут **уже на prod** (Render: `assessment-api-fm0e.onrender.com`, URL из `VITE_API_BASE_URL`). Dev-фронт ходит туда по умолчанию |
| **Узлы / симуляция** | Новый роут ещё не на prod — схема с состояниями на фронте, без `fetch` к незадеплоенным эндпоинтам |

**Запрещено:** лаба, для которой нужно «подними `server` локально» или «пропиши `VITE_API_BASE_URL=localhost`» — такой live **не делаем**. Либо деплой роута на удалённый API **до** live-лабы, либо узлы / фронт-only.

Самопроверка перед live-роутами:

- Эндпоинт будет на prod assessment-api до merge, **или** тема обходится без сети?
- Пользователь открывает только фронт (Pages / `npm run dev` в `app/`) — стенд уже работает?

Роут только в локальном `server/` и не на Render → **не live**: симуляция на «Проблеме», конфиг origin/CDN — на «Код». `hasApi` в `parseTopicMd.ts` — только для тем с **задеплоенным** удалённым API.

5. Если картина есть — набросать: живой мини-стенд **или** 3–6 узлов / 2–3 UI-сцены; 2–4 состояния (`idle` → шаг → ok / ошибка). Ghost-кейсы (2 на паттерн) + **Запустить** (при пошаговости — опционально **Шаг**). Клик по кейсу **не** стартует прогон.
6. Для каждого кейса — **1 предложение**, что он показывает (`CASE_BRIEF`).
7. Только потом — сниппеты «Код» и проводка.

### Без визуализации

Когда **прямо нечего** показать на стенде (нет состояний, нет DOM/API-эффекта, узлы были бы декоративным пересказом теории) — **не надо** схемы, анимации, GSAP, `LabVizPanel`, статичных блоков-узлов и кнопки **Запустить**.

Эталон: `app/src/topics/ts-declaration-files/TsDeclarationFilesLab.tsx` (`.d.ts`: ambient vs `"types"` в package) — смысл в сниппетах на «Код», на «Проблеме» только ghost-кейсы + `pain` + brief.

Правила для такого режима:

- Вкладки те же две; первая — **Код** с 2–3 реальными файлами и `←`.
- На «Проблеме»: ghost-кейсы (если кластер) → `pain` + brief выбранного кейса. **Без** картины, **без** прогона, **без** лога «для вида».
- Не компенсировать отсутствие схемы стеной текста или `log(...)`.
- Скилл [`assessment-lab-visualizations`](../assessment-lab-visualizations/SKILL.md) не читать.
- Антипаттерн «только лог без картины» **не** про этот режим: там лог притворялся уроком *вместо* нужной схемы. Здесь схемы не должно быть изначально.

### Лимиты

| Что | Лимит |
|-----|--------|
| `pain` | 1–2 предложения (про паттерн / механизм) |
| описание кейса | **1** предложение про **выбранный** кейс |
| кейсы на **видимый** механизм | **2–3**, не 4–5 |
| сниппеты | **2–3** файла |
| схема / стенд | 3–6 узлов **или** 2–3 UI-сцены **или** один живой мини-стенд; **или** нет картины (§ «Без визуализации») |
| лог за прогон | 2–5 строк; не дублировать `pain` / brief; без картины — лога нет |

Кластер паттернов: переключатель не считается «4–5 сценариями». На выбранный паттерн — 2 контраста.

### Схема / стенд

Если механизму есть что показать — на «Решении проблемы» картина **норма**. **Запустить** обновляет её; лог — квитанция (статус, заголовок), не урок.

Вид картины — по таблице в «Дизайн до кода». CorsLab — эталон live-API/HTTP; `react-portals` / `react-error-boundaries` — эталон **живого механизма** (не подменять узлами, если глаз должен увидеть clip / portal / fallback).

Если нечего показать — § «Без визуализации»: без `LabVizPanel`, без анимации, без **Запустить**. **Запрещено** подменять нужную схему одним только `log(...)`. **Запрещено** клеить фейковые статичные узлы, когда картина не добавляет понимания сверх вкладки «Код».

Live-API и живой механизм — двигатель стенда внутри `LabVizPanel`; стиль chrome — только [`assessment-lab-visualizations`](../assessment-lab-visualizations/SKILL.md).

### Анимация

Только если есть картина / прогон. Без визуализации — GSAP не подключать.

- Не `gsap.fromTo` всех узлов на каждый `phase` (дёрганье).
- `gsap.timeline()`: шаг **0.5–0.7 с**, `ease: "power2.inOut"`, твин только активного элемента (карточка, пакет, слот).
- Состояния узлов — CSS `transition` **0.35–0.45 с**.
- Перед новым прогоном `tl.kill()`.
- `prefers-reduced-motion: reduce` → сразу финальный кадр.
- **Пошаговая визуализация:** если картина идёт кадрами / фазами (курсор, стек, очередь, `next()`…), можно добавить кнопку **Шаг** рядом с **Запустить**: один клик = **один** кадр анимации, а не весь прогон. **Запустить** по-прежнему проигрывает всё сразу. Не подменять **Запустить** только шагами; не вешать шаг на ghost-кейс.

### Кластер паттернов

Несколько механизмов **можно**, если на экране **одна** схема + ghost-переключатель (как `algorithms-stack-hashmap`).  
Запрет — «полотно» `algorithms-graphs-list` (список + граф + BFS + DFS сразу).

### Антипаттерны

- Только лог, без картины — как `sql-injection` / соседние security до рерайта (когда схема **нужна**)
- Фейковая схема из статичных узлов / «Запустить» без смысла — когда механизму нечего показать (вместо § «Без визуализации»)
- **Узлы вместо живого эффекта**, когда механизм можно показать тем же API / через существующий `server`+БД (`#root → Modal` вместо `createPortal`; анимация «query» вместо реального `/api/…` + Postgres)
- Молча выбрать только `LabNode`, когда в FRANKENSTEIN у темы **API**/**оба** или live уже возможен — без вопроса с описанием варианта
- Кнопка кейса сразу запускает прогон (нужны ghost + **Запустить**, если прогон есть)
- Горизонтальный поток `A → B → C` для любой темы «потому что CorsLab»
- 4–5 кейсов на один видимый механизм
- Полотно нескольких схем сразу
- Мета-фразы в UI про «настоящие файлы» и `←` (см. ниже)
- Meta-инструкции про UI: «Выберите паттерн и кейс — схема ещё не играет», «Нажмите Запустить и смотрите…», «затем нажмите Запустить»
- Кнопки **под** схемой / текстом (нужны **сверху**)
- Статичный `ol.steps` с общими «как пользоваться стендом» вместо описания выбранного кейса

## Обязательный каркас

- `JsLabShell` + `InteractiveCodePanel`
- Две вкладки: **Код** (первая) и **Решение проблемы**
- **Не** передавать `sandbox` / не делать «Песочницу»
- `TOPIC_ID` = id темы; ключ LS: `assessment-lab-code:${topicId}:${snippetId}` (пишется только после правки кода; эталон сам по себе не сохраняется)

Проводка:

1. `hasLab` в `app/src/content/parseTopicMd.ts`
2. import + ветка в `TopicLab` в `app/src/pages/TopicPage.tsx`
3. файл `app/src/topics/<slug>/<Name>Lab.tsx`

## Вкладка «Код»

- Сниппеты = **реальные** файлы/фрагменты (`package.json`, `webpack.config.js`, `store.js`, …), не псевдо-`console.log`-демо.
- Важное помечать **в коде**: `// ← HMR`, блоки `/* LOADERS */`.
- Node / `require` / неисполняемое → `executable: false` (консоль и «Выполнить» скрыты).
- 2–3 сниппета-файла по подтемам; у кластера — **тот же** ghost-переключатель, что на «Решении проблемы», и сниппеты выбранного паттерна (эталон: `algorithms-stack-hashmap`).

### Высота редактора (flex + скролл)

Два слоя — **layout** и **контент**:

| Слой | Цель | Как |
|------|------|-----|
| **Layout** | Редактор занимает весь док вкладки «Код» | Flex-цепочка + `fillAvailable` |
| **Контент** | Сниппет по возможности виден целиком | ~15–25 строк, без лишнего boilerplate |

**Layout (обязательно):**

- `JsLabShell` с `fill={true}` (дефолт) — не отключать без причины.
- Ghost-табы + `InteractiveCodePanel` → обёртка **`shell.codePane`** из [`JsLabShell.module.css`](../../app/src/components/lab/JsLabShell.module.css), не локальный `.codePane` в CSS топика.
- Запрет: `.codePane { display: flex }` без `flex: 1; min-height: 0`.
- `InteractiveCodePanel` — `fillAvailable` по умолчанию (не передавать `false`).
- Цепочка: `JsLabShell rootFill` → `LabTabs .panel` → `shell.codePane` → `InteractiveCodePanel rootFill`.
- Эталон: `patterns-mediator-composite-memento`, git-лабы с `shell.codePane`.

**Когда отключать растяжку дока (важно для высоты):**

Если из‑за высоты дока редактор во вкладке «Код» начинает выглядеть «сжатым» (в частности, контент обрезается/упирается в блок со ссылкой внизу вкладки и приходится скроллить фрагменты вместо всего контента лабы), отключите растяжку дока для конкретной лабы:

- в `JsLabShell` поставьте `fill={false}`;
- для надёжности в `InteractiveCodePanel` можно также явно передать `fillAvailable={false}`.

Тогда скролл должен идти по всей вкладке/лабе, а не «частями» внутри редактора.

**Контент (стремиться без скролла):**

- Сниппет укладывать в ~**15–25 строк** видимой области типичного дока.
- Обрезать шум (`#!/usr/bin/env`, длинные комментарии), оставлять блок с `←`.
- 2–3 файла на паттерн — лучше короче, чем одна простыня.
- Самопроверка: вкладка «Код» — короткий эталон **без** внутреннего скролла; длинный конфиг может скроллиться **внутри** CodeMirror.

Внутренний скролл **допустим** у намеренно полного файла (`webpack.config.js`). **Недопустим** скролл из‑за крошечного редактора при коротком сниппете — это баг flex-цепочки, не «слишком длинный код».

Плохо: 8 строк `.gitattributes` «еле видны» в редакторе высотой ~72px.  
Хорошо: тот же сниппет на всю высоту дока; скролл только если файл действительно длинный.

### Группа React (`groupId: "react"`)

Сниппеты `.tsx` / `.jsx` и UI-компоненты самой лабы — **стрелочные компоненты** на **React + TypeScript**:

- `export const Modal = ({ open }: Props) => { … }` / `export const App = () => (…)`
- Типы пропсов: `type Props = { … }` или `Props` рядом с компонентом
- **Не** `export function Modal(…)`, **не** `class … extends Component` (кроме редких API, где класс обязателен: например legacy `ErrorBoundary` через class — только если тема именно про это)
- Эталон стиля: `react-error-boundaries` (`ReactErrorBoundariesLab.tsx`)

### Не писать в UI

В `intro` / `note` / `lead` / `pain` / `hint` / описании кейса **запрещены** мета-фразы:

- «Настоящие файлы проекта»
- «важное выделено комментариями `← …`»
- «артефакты с пометками»
- «Выберите паттерн / кейс…», «схема ещё не играет», «Нажмите Запустить и смотрите…»

`intro` — про **содержание темы**. Пометки `←` — только внутри кода.

### Не эхо промпта и стиля кода

В сниппетах, комментариях `← …`, блоках `/* … */`, JSDoc, `note` / `intro` / `lead` / `pain` / brief **запрещено** отражать просьбы из промпта автора и «как мы пишем код» как тему урока.

Пометки `←` — только про **механизм темы** (`HMR`, `render-phase`, `FallbackComponent`, `patch`), не про формат/стиль по запросу.

Плохо:

```text
// FALLBACK ← стрелка, не класс
// APP ← только стрелки, без class
/* Live stand: без class по просьбе */
note: «В приложении — только стрелки…»
```

Хорошо:

```text
// FALLBACK ← экран ошибки виджета
// BOUNDARY ← изоляция сбоя в main
// ← render-phase
note: '`ErrorBoundary` оборачивает виджет; `FallbackComponent` — запасной UI.'
```

## Вкладка «Решение проблемы»

### Раскладка (обязательна)

Порядок сверху вниз:

1. Ghost паттерн (если кластер)
2. Ghost кейсы
3. Если есть картина: **Запустить** (+ опционально **Шаг**) + **Сброс**
4. `pain` (механизм / паттерн) + краткое описание **выбранного** кейса
5. Схема — **только если** есть что визуализировать (иначе пропуск; § «Без визуализации»)
6. `hint` — только **после** полного прогона / последнего шага (итог); без прогона — не нужен
7. Короткий лог (`useLabLog` / `LabLogView`) — только при прогоне

Блок кнопок **всегда сверху**, содержимое (текст → схема → лог) — ниже.

Эталон с картиной: `PatternsMediatorCompositeMementoLab.tsx`.  
Эталон без картины: `TsDeclarationFilesLab.tsx`.

### Текст под кнопками

| Блок | Что писать |
|------|------------|
| `pain` | Зачем механизм в работе/учёбе (1–2 предложения), без лексики собеседований |
| описание кейса | **1 предложение**: что показывает **текущий** кейс (контраст / сценарий). Меняется при смене кейса |
| `hint` | Итог прогона («Итог: …»), не инструкция до запуска |
| лог | Квитанция (статус, заголовок), не урок и не дубль `pain`/brief |

Плохо:

```text
Выберите паттерн и кейс — схема ещё не играет.
Нажмите Запустить и смотрите, что изменилось на картинке.
```

Хорошо (кейс `hub`):

```tsx
<p className={shell.hint}>
  Поля шлют <code>change</code> в хаб; Submit читает <code>submitEnabled</code> из снимка.
</p>
```

Ссылки на «Код» уместны («см. store.js»), без рассказа про формат оформления.  
**Запустить** меняет схему; лог не заменяет картинку.

### Простые слова (доходчивость)

На «Решении проблемы» (и в `lead`, ghost-табах, подписях схемы, логе) — **простые описания словами**, чтобы было доходчивее: что происходит, кто кому шлёт, что изменилось. Как коллеге, который не живёт в жаргоне темы.

Термины и API по-прежнему в `<code>` / backticks. Вокруг них — обычный русский: сосед / роутер / напрямую / дом / интернет, не голый `on-link`, `SNAT`, `prefix miss`, `WAN`.

Куда относится:

| Место | Как |
| --- | --- |
| `lead`, `pain`, brief, `hint` | житейская фраза + термин в `<code>` |
| ghost паттерн / кейс | понятный ярлык («Своя сеть», «сосед рядом»), не внутреннее имя механизма |
| узлы схемы, `meta`, пакет | те же простые слова, что в `pain` |
| лог | короткие фразы на том же языке, не англ. квитанция |
| `intro` / `note` | тоже доходчиво; жаргон в backticks |

Эталон: `app/src/topics/network-ip-basics/NetworkIpBasicsLab.tsx`.

Плохо:

```text
Адрес читают с префиксом: 10.0.2.15/24. Совпадение — on-link, иначе пакет на gateway.
Кейс: SNAT наружу. Лог: prefix miss / table miss. Узлы: host → prefix check → next hop.
```

Хорошо:

```text
Число после / говорит, кто в одной сети с компьютером. Сосед — пакет идёт напрямую; чужой адрес — сначала на роутер.
Кейс: выход в интернет. Лог: роутер меняет адрес. Узлы: компьютер → одна сеть? → напрямую / через роутер.
```

Не раздувать `pain` сверх 1–2 предложений и не превращать лог в урок: простота — в словах, не в объёме.
