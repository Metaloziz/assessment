### Когда лаба обязательна

- Уровень **middle** или **senior** (новые темы и те, которые правим) — **лаба обязательна**.
- Уровень **junior** — лаба только если явно попросили; по умолчанию только теория.

### Просто и наглядно

Это **раздел правил**, не третья вкладка UI. Вкладки по-прежнему две: **Код** и **Решение проблемы**. Схема живёт на «Решении проблемы».

На экране — **одна** схема выбранного механизма (если схеме есть место). За 10–20 секунд ясно: что сломано, что выбрать, что нажать, что изменилось. Если нечего визуализировать — см. § «Без визуализации» / скилл лаб: без фейковых узлов и **Запустить**.

Сначала стенд (или решение «картины нет»), потом сниппеты:

1. Есть ли что показать глазу? Если нет — режим без картины; смысл на вкладке «Код». Эталон: `ts-declaration-files`.
2. Сверить тему с [`docs/FRANKENSTEIN_PLAN.md`](docs/FRANKENSTEIN_PLAN.md) (API / оба) и с тем, что уже есть в `server/` / БД / smoke. Если live возможен — **не** молча клеить только `LabNode`: задать вопрос с описанием варианта и дождаться ок (детали — скилл лаб § «Дизайн до кода»).
3. Иначе / после согласия: механизм темы **или** кластер с переключателем (на экране одна картина).
4. Вид картины: **живой механизм** / **живые UI-образцы** / **узлы**. Горизонтальный поток `A → B → C` — только если тема про пайплайн запроса.
5. Картина: мини-стенд **или** 3–6 узлов / 2–3 сцены — см. скилл визуализаций.
6. Ghost-кейсы (2 на видимый механизм) + **Запустить** при наличии прогона (опц. **Шаг**). Клик по кейсу не стартует прогон.
7. Для каждого кейса — **1 предложение**, что он показывает.
8. Затем вкладка «Код» и проводка.

| Что | Лимит |
| --- | --- |
| `pain` | 1–2 предложения (механизм / паттерн) |
| описание кейса | **1** предложение про **выбранный** кейс |
| кейсы на видимый механизм | **2–3** |
| сниппеты | **2–3** файла |
| схема / стенд | 3–6 узлов **или** 2–3 UI-сцены **или** живой мини-стенд **или** нет картины |
| лог за прогон | 2–5 строк; без картины — лога нет |

Плохо: четыре кнопки сценариев, каждая сразу гоняет прогон; или только `log(...)` вместо нужной схемы; или статичные узлы «для галочки» у чисто декларативной темы.  
Плохо: `ol.steps` «Выберите паттерн… / Нажмите Запустить…»; кнопки под схемой.  
Хорошо (с картиной): кнопки **сверху** → `pain` + brief → схема; ghost + **Запустить**; лог — квитанция.  
Хорошо (без картины): ghost → `pain` + brief; файлы на «Код» (`ts-declaration-files`).

Плохо: полотно всех механизмов сразу (как graphs-list).  
Хорошо: переключатель + одна картина (как stack/hash). Остальное — в теории справа.

### Визуализации

Если механизму есть что показать — схема на «Решении проблемы» **норма**. **Запустить** обновляет картинку; лог — квитанция, не урок.

Метафору / вид картины выбирать **под тему**, не копировать CorsLab. CorsLab — эталон live-API/HTTP.

Если эффект механизма **виден в браузере** тем же API (portal, overflow clip, error boundary, live request) — картина = **живой мини-стенд**, не схема из `LabNode`. Эталоны: `react-portals`, `react-error-boundaries`. Если live возможен (в т.ч. по FRANKENSTEIN + существующий `server`/БД) — сначала вопрос с описанием варианта, код после согласия; см. [`skills/write-assessment-labs/SKILL.md`](skills/write-assessment-labs/SKILL.md). Подробности стиля — в скилле визуализаций (§ «Живой механизм»).

Если механизм — **визуальный look** (дизайн-система, токены, типографика, contrast) — картина = **живые образцы UI** (2–3 сцены с контролами), а не стек абстрактных `LabNode`. Эталон: `layout-design-system`. Подробности — в скилле визуализаций (§ «Живой UI-образец»).

Иначе — узлы / метафора структуры (стек, граф, каталог…).

### Без визуализации

Нечего анимировать и нечего честно нарисовать (чистый синтаксис, `.d.ts`, декларативный конфиг без состояний) — **не** клеить `LabVizPanel`, статичные узлы, GSAP и **Запустить**. На «Проблеме» — ghost + `pain` + brief; урок в файлах на «Код». Эталон: [`TsDeclarationFilesLab.tsx`](app/src/topics/ts-declaration-files/TsDeclarationFilesLab.tsx).

Учить механизм **только** строками лога (когда схема **нужна**) — нельзя: это другой антипаттерн, не путать с режимом без картины.

Анимация: только при наличии картины — `gsap.timeline()`, шаг 0.5–0.7 с, `power2.inOut`; не `fromTo` всех узлов на каждый phase; CSS `transition` 0.35–0.45 с на состояния; `tl.kill()` перед новым прогоном; `prefers-reduced-motion: reduce` → финальный кадр.

Если визуализация **пошаговая** (кадры / фазы), можно добавить кнопку **Шаг**: один клик = один кадр анимации. **Запустить** по-прежнему проигрывает весь прогон. **Шаг** не обязателен и не заменяет **Запустить**.

Единый стиль: [`skills/assessment-lab-visualizations/SKILL.md`](skills/assessment-lab-visualizations/SKILL.md). Workflow и чеклист — [`skills/write-assessment-labs/SKILL.md`](skills/write-assessment-labs/SKILL.md). Live-API — двигатель стенда, не замена схеме.

## Формат (обязателен для новых)

Две вкладки, без «Песочницы» (третьей вкладки нет):

1. **Код** (первая, активна по умолчанию) — `InteractiveCodePanel`
2. **Решение проблемы** — ghost паттерн (если кластер) → ghost кейсы → при наличии картины: **Запустить** (+ опц. **Шаг**) + **Сброс** → `pain` + brief кейса → схема (если есть) → hint после прогона → лог (если есть прогон)

Оболочка: `JsLabShell` + `InteractiveCodePanel`.  
`sandbox` **не передавать**.  
`defaultTab: 'code'` (дефолт shell/tabs).

### Ссылка на стенд

На вкладках **Код** и **Решение проблемы** — компактный футер [`LabStandLink`](app/src/components/lab/LabStandLink.tsx): иконка «открыть в новой вкладке» + кнопка «скопировать». Полный URL **не** показывать inline (доступен в `title` / screen reader). Подключение — в [`LabTabs`](app/src/components/lab/LabTabs.tsx).

Ключ LS: `assessment-lab-code:${topicId}:${snippetId}`. Пишется **только после правки** в редакторе; эталон без правок в LS не кладётся. «Сброс кода» чистит ключ, консоль и скрывается, если код снова совпадает с эталоном и запуска не было.

### Вкладка «Код» — настоящий код

Сниппеты во вкладке **Код** — это **реальный код** (как в проекте: `package.json`, `webpack.config.js`, модули, конфиги), а не псевдо-объекты «для console.log» и не абстрактные таблицы в коде.

- Показывать цельный файл или осмысленный фрагмент файла, который можно узнать в репозитории.
- Участки, важные для темы, **выделять комментариями** в самом файле (`// ← HMR`, `// LOADERS`, блок `/* … */`), а не отдельной «шпаргалкой» вместо кода.
- Эталоны с `require` / Node API, которые песочница не исполнит — `executable: false` (консоль и «Выполнить» скрыты; без плейсхолдеров вроде «эталон без запуска»).
- Допустимы **2–3** сниппета-файла по подтемам; каждый — настоящий артефакт, не demo-строка.
- Кластер паттернов: на «Код» — **те же** ghost-табы, что на «Решении проблемы»; `InteractiveCodePanel` показывает файл(ы) выбранного паттерна. Эталон UX: [`AlgorithmsStackHashmapLab.tsx`](app/src/topics/algorithms-stack-hashmap/AlgorithmsStackHashmapLab.tsx).

#### Группа React (`groupId: "react"`)

Код в сниппетах и UI-компоненты лабы — **стрелочные компоненты** на **React + TypeScript**:

```tsx
type Props = { open: boolean; children: React.ReactNode };

export const Modal = ({ open, children }: Props) => {
  if (!open) return null;
  return <div className="overlay">{children}</div>;
};
```

- Форма: `export const Name = (props: Props) => { … }` или `=> (…)` для короткого JSX.
- **Не** `export function Name(…)`, **не** class-компоненты — кроме случаев, где API темы требует class (например сам `ErrorBoundary` как class).
- Эталон: [`ReactErrorBoundariesLab.tsx`](app/src/topics/react-error-boundaries/ReactErrorBoundariesLab.tsx).
- В `←` / `note` / `intro` **не** писать про стиль («стрелки», «не class») — только про механизм темы (см. ниже).

#### Не писать в UI инструкции агенту

Правило «настоящие файлы + комментарии `← …`» — для автора лабы, **не** для текста на экране.

- В `intro`, `note`, `lead`, `pain`, `hint`, brief кейса **не** писать мета-фразы вроде: «Настоящие файлы проекта», «важное выделено комментариями `← …`», «артефакты с пометками», «Выберите паттерн и кейс — схема ещё не играет», «Нажмите Запустить и смотрите…».
- **Не** описывать проводку стенда: «Живые `/api/lab/…`», «учебные роуты», «на Render», перечень эндпоинтов вместо смысла метрики. Пути и JSON — в сниппетах; в `lead` / `pain` / brief — зачем механизм, не как устроена лаба.
- `intro` — коротко **о содержании темы** (что смотреть в файлах), не о формате оформления.
- Под кнопками — описание **выбранного кейса**, не инструкция «как пользоваться стендом».
- Пометки `← …` остаются **только внутри кода** сниппетов.

Плохо (intro): `Настоящие файлы проекта. Важное для темы выделено комментариями ← ….`  
Хорошо (intro): `` `webpack-merge`: common / dev / prod; HtmlWebpackPlugin, Terser, analyzer. ``

#### Не эхо промпта и стиля кода

В сниппетах, `// ← …`, `/* … */`, JSDoc и подписях UI **не** отражать просьбы из промпта («не используй классы», «только стрелки») и не превращать стиль кода в тему урока.

`←` — про механизм (`HMR`, `render-phase`, `patch`), не про «как писали по запросу».

Плохо: `// FALLBACK ← стрелка, не класс`, `note: «только стрелки…»`.  
Хорошо: `// FALLBACK ← экран ошибки виджета`, `note: «FallbackComponent — запасной UI»`.

Плохо: `const roles = [['css-loader', '…']]; console.log(roles)`.  
Хорошо: полный `webpack.config.js` с помеченными `module.rules` и `plugins`.

### Миграция legacy

Классика (`LabCodePanel` + «Песочница») — не создавать. Если касаешься темы со старой лабой — мигрируй на этот стандарт, если объём разумный.

### Редактор

Редактор **заполняет** свободное место в доке вкладки «Код»; при переполнении — скролл **внутри** CodeMirror, не сжатый viewport.

**Flex-цепочка** (все звенья обязательны):

1. `JsLabShell` — `fill={true}` (дефолт)
2. `LabTabs` — `.panel` с `flex: 1; min-height: 0`
3. `shell.codePane` — [`JsLabShell.module.css`](app/src/components/lab/JsLabShell.module.css): `flex: 1; min-height: 0`
4. `InteractiveCodePanel` — `rootFill` + `fillAvailable` (дефолт `true`)

Если ghost-табы + `InteractiveCodePanel` — обёртка **`shell.codePane`**, не локальный `.codePane` без `flex: 1`. Выключать `fill` / `fillAvailable` — только по явной просьбе.

**Сниппеты:** стремиться уложить эталон в ~15–25 строк без внутреннего скролла; длинный scroll допустим у намеренно полного файла. Крошечный редактор при коротком коде — баг layout, не повод урезать сниппет.

**«Сброс кода»:** кнопка **не рендерится**, пока код совпадает с эталоном **и** пользователь не нажимал «Выполнить». Автозапуск при mount / debounce после правки **не** считается «запуском». Показывать, если код отличается от эталона (в т.ч. черновик из LS) **или** был явный клик «Выполнить». Сброс возвращает эталон, чистит LS и консоль.

## Текст с цветными вставками (как в теории)

Термины, API, имена методов/классов — **всегда** в инлайн-коде. Стиль уже в CSS: фон `rgba(255,255,255,0.06)`, цвет `#ce9178`.

| Где | Как писать |
| --- | --- |
| **Решение проблемы** (`pain`, brief кейса, `hint`, `lead`) | JSX: `<code>getPrototypeOf</code>` |
| **Код** (`intro`, `note` у сниппетов) | Строка с backticks: `` `getPrototypeOf` `` — `InteractiveCodePanel` сам рендерит в `<code>` |

### Примеры

**Проблема:**

```tsx
<p className={shell.pain}>
  Метод лежит на <code>Person.prototype</code>, не на экземпляре. Смотрите{' '}
  <code>Object.getPrototypeOf</code>.
</p>
```

**Код (intro / note):**

```tsx
intro="Смотрите связи: `prototype`, `getPrototypeOf`, `extends`, `new`."
note: '`target` — источник; `currentTarget` — узел с обработчиком.'
```

- ✅ Оборачивать: `class`, `new`, `Map`, `localStorage`, `#field`, `::part`, имена API.
- ❌ Голый текст терминов без backticks / `<code>` во вкладке «Код» или в pain / brief / hint.

Тон «Проблемы»: житейский, без глоссария. Детали API — в «Код» и в теории справа.

**Простые слова (доходчивость).** `pain`, brief, `hint`, `lead`, ghost-табы, подписи узлов и лог объясняют *что происходит* обычным русским, не стеной жаргона. Термин в `<code>`, вокруг — кто, куда, что изменилось. Эталон: [`NetworkIpBasicsLab.tsx`](app/src/topics/network-ip-basics/NetworkIpBasicsLab.tsx) («сосед рядом», «через роутер», не `on-link` / `SNAT` / `prefix miss`). Не раздувать объём: лимиты `pain` / brief / лога те же. Workflow — [`skills/write-assessment-labs/SKILL.md`](skills/write-assessment-labs/SKILL.md) § «Простые слова».

### Раскладка «Решение проблемы» (обязательна)

Порядок сверху вниз:

1. Ghost паттерн (если кластер) → ghost кейсы → при картине: **Запустить** (+ опц. **Шаг**) + **Сброс**
2. Короткий `pain` + **1 предложение** про выбранный кейс
3. Схема — только если есть что визуализировать
4. `hint` только после полного прогона (если прогон есть) → `LabLogView` при прогоне

Без картины: ghost → `pain` + brief; без **Запустить**, схемы, лога. Эталон: [`TsDeclarationFilesLab.tsx`](app/src/topics/ts-declaration-files/TsDeclarationFilesLab.tsx).

Блок кнопок **всегда сверху**, содержимое ниже. Эталон с картиной: [`PatternsMediatorCompositeMementoLab.tsx`](app/src/topics/patterns-mediator-composite-memento/PatternsMediatorCompositeMementoLab.tsx).

**Запустить** меняет схему, а не только лог. При пошаговости **Шаг** двигает схему на один кадр.

В тексте под кнопками **не** писать meta-инструкции вроде «Выберите паттерн и кейс — схема ещё не играет» / «Нажмите Запустить и смотрите…». Вместо этого — 1 предложение, что показывает **текущий** кейс. `hint` до прогона не показывать (или не писать «затем нажмите Запустить»).

## Кнопки — только `LabButton`

Компонент: [`app/src/components/lab/LabButton.tsx`](app/src/components/lab/LabButton.tsx). Варианты через props:

| Prop | Назначение |
| --- | --- |
| `variant="primary"` | **Запустить** / **Прогнать** — главное действие |
| `variant="secondary"` | **Сброс**, опционально **Шаг** (один кадр), прочие действия |
| `variant="ghost"` + `active` | Табы паттерна / кейса / сниппетов |
| `size="sm"` | Компактные ghost-табы |

```tsx
<LabButton variant="ghost" size="sm" active={caseId === 'ok'} onClick={…}>OK</LabButton>
<LabButton variant="primary" onClick={run}>Запустить</LabButton>
<LabButton variant="secondary" onClick={step}>Шаг</LabButton>
<LabButton variant="secondary" onClick={reset}>Сброс</LabButton>
```

- ❌ Не использовать `shell.btn` / `shell.btnPrimary` в новых лабах.
- ❌ Не плодить локальные стили кнопок «чуть другие» на одной странице.
- ❌ Не вешать прогон на кнопку кейса: кейс только выбирает, **Запустить** играет схему.

Лабы Redux пишем на **React + TypeScript** с `@reduxjs/toolkit` и `react-redux`:
